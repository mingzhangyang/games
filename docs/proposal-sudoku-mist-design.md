# 《雾隐九宫 Sudoku in the Mist》设计方案

> 状态：设计提案 · 2026-10-18；P0 模型（§14）、P1 可玩原型（§15）与 P2 每日一雾 / 排行榜 / 星级（§16）已完成，待试玩
> 方向：A「迷雾数独」为骨架 + B「推理即得分」为反馈；外观借东方晨雾意象
> 工作名与 id 见 §13，可改

## 1. 一句话定义

一盘标准 9×9 数独，开局被晨雾笼罩；**每一个推理出来的数字都会拨开周围的雾**，露出下一步需要的线索。分数不看快慢，看你每一步**推理得有多深**——猜对的数字不算本事。

## 2. 设计原则

1. **规则零改动**：行、列、宫 1–9 不重复，解唯一。爱好者认的那层不动，特色全部放在「信息、反馈、目标」三层。
2. **雾只藏信息，不撒谎**：雾里是什么，揭开后就是什么；渲染层和 DOM 永远拿不到雾中格的内容（§9.3）。
3. **永不卡死**：任何合法的推进顺序都不会把玩家逼到「只能猜」的局面——由构造保证、由校验器锁住（§7.3）。
4. **奖励看见，不奖励手快**：排名按推理分，时间只展示不排名。
5. 先验证好不好玩，再做美术和产品化（同萤火信号的 Prototype 路线）。

## 3. 核心体验

- **开局**：只有一小片视野（例如一宫加零星几格），其余是雾。你看得见的线索很少，但足以推出第一个数字。
- **推进**：每填对一格，它周围 8 格的雾散开。露出来的可能是新的已知数字，也可能是空格。盘面像晨雾被阳光一点点照透。
- **穿雾**：有时候一个数字推得出来，但它在雾里——比如某行只剩一个空位在雾中。你可以**直接把数字落进雾里**，雾随之破开，这一步额外加分。这是本作最想做出来的「啊哈」时刻。
- **结算**：回放你的整条推理链：哪一步用了什么技巧、哪几步穿了雾、哪一步是侥幸猜的。

## 4. 规则

### 4.1 格子的三种状态

| 状态 | 玩家看到 | 说明 |
|---|---|---|
| 雾中 `fog` | 只有雾 | 不知道它是题面给出的数字还是空格 |
| 可见·题面 `given` | 墨色数字 | 雾散后露出的题面数字 |
| 可见·空格 / 已填 `open` / `placed` | 空格或玩家填的数字 | |

雾中的题面数字与雾中的空格**对玩家完全等价**：都是「未知格」。

### 4.2 落子

- 玩家可以在任何**未确定**的格子落子：可见空格，或雾中格（穿雾）。
- **填对**：数字落定（不可撤销，因为它是对的），触发揭雾（§4.3），按 §5 计分。
- **填错**：立即退回，墨迹晕开一下，扣分并打断连推（§5.3）。错的数字从不留在盘面上——这保证「当前已知信息」永远是真的，§5 的推理判定才有意义。
- 若雾中格其实是题面数字，玩家推出并落下它，同样计分、同样触发揭雾：**先推出来比等它被揭开更值钱**，这是排序策略的一部分。

### 4.3 揭雾

- 每次**落子成功**，揭开落子格周围的雾。揭雾核按章节二选一（P0 实测后的决定，见 §14）：
  - `box`：以落子格为中心的 3×3（周围 8 格）——第一章，雾散得快、好上手；
  - `cross`：落子格 + 上下左右 4 格——之后的章节与每日题。雾留得更久（走 20 步还剩约 1/3），穿雾次数约是 `box` 的两倍。
- 被揭开的题面数字**不会自动连锁揭雾**。但如果一个原先藏在雾中的题面数字被别的落子提前揭开，它保留一次**手动拨雾**机会：该格以微光标记，玩家可以点按它，再次揭开自己的揭雾核（不计分、不算落子、会中断连推）。开局已可见的题面数字没有这项机会。这样既不让雾自动传染，也不会让合法落子顺序悄悄吞掉必要的揭雾动作。
- 后期章节的特殊格（§8）可以改变揭雾范围，但规则始终是「落子触发、无连锁」。

### 4.4 铅笔标记

- 手动铅笔标记随意用，不影响计分。
- **不提供自动候选数**：自动候选会把最基础的推理（§5 的 T1/T2）直接替玩家做完，与本作的核心反馈冲突。「晴空模式」可以考虑开放（§8.4）。

## 5. 推理即得分

### 5.1 每一步的「推理档位」

玩家落子的那一刻，取**当前知识** K = 所有可见的题面数字 + 已落子数字。雾中格一律视为未知。

用一个模仿人类解题的技巧梯（§7.1）判断这一格：

> 这一格的档位 = 最小的 t，使得「只用 ≤ t 档的技巧，从 K 出发反复推导直到不动点」能确定这一格的值。

找不到任何 t ≤ T4 能确定 → 这一步是**侥幸**（玩家猜对了）。

注意这里取的是推导**闭包**：如果玩家在心里先推了别的格、再推到这一格，仍然按闭包算出它的档位，不吃亏。

### 5.2 档位与基础分

| 档位 | 技巧 | 基础分 |
|---|---|---|
| T1 | 唯一空位（单元只剩一格）、宫内隐性唯一 | 10 |
| T2 | 行/列隐性唯一、唯余数（裸单） | 20 |
| T3 | 区块排除（pointing / claiming）、显性/隐性数对 | 40 |
| T4 | 显性/隐性三数组、X-Wing | 80 |
| — | 侥幸（当前信息推不出） | 0 |

MVP 只到 T4。更高阶技巧（XY-Wing、链）不进出题器，确保题目不需要它们。

### 5.3 乘数与扣分

- **穿雾**：落在雾中格 ×1.5。
- **连推**：连续第 n 次推理落子（非侥幸、非提示）乘 `1 + 0.1 × min(n − 1, 10)`，上限 ×2.0。
- **侥幸**：0 分，连推清零，结算回放里标出。
- **填错**：−20（总分不低于 0），连推清零。
- **提示**（点灯，§6.3）：这一步 0 分，连推清零。

单步分 = `round(基础分 × 穿雾 × 连推)`。

量级估算：一盘约 50–55 次落子；理论上限约 55 × 80 × 1.5 × 2 ≈ 13,200。排行榜 `maxScore` 取 50,000 留余量。P0 机器人实测：第一、二章随机推理玩家约 1,120–1,340 分，贪分玩家约 1,140–1,520 分（见 §14 的计分深度问题）。

### 5.4 这套计分带来的策略

- 高档位格**越早落越值钱**：同一格，等更多信息出现后再填可能只剩 T1。先看出深层推理是被奖励的。
- 穿雾 + 高档位叠乘，是高分的主要来源。
- 暴力试数会被重罚：试错扣分，试对也是侥幸 0 分。

## 6. 操作

### 6.1 输入

- **先选格再选数**（默认）和**先选数再点格**两种方式都支持；先选数时高亮盘面上所有该数字及其行列宫。
- 手机：盘面下方 1–9 数字键 + 铅笔切换 + 擦除（只擦铅笔）+ 点灯。数字键 ≥44px。
- 键盘：方向键移动、`1–9` 落子、`Shift+1–9` 或 `N` 切换铅笔、`Backspace` 擦铅笔、`H` 点灯、`P`/`Esc` 暂停（站点惯例）。
- 雾中格**可以被选中**（穿雾需要），选中时只显示选框，不泄露任何内容。

### 6.2 反馈

- 落子成功：数字墨迹落定 → 邻域雾在约 600ms 内散开；浮字显示 `+40 区块 ×1.5 穿雾`。
- 档位用**文字缩写 + 颜色**双编码（色盲友好），不只用颜色。
- 填错：墨迹晕开退回，短促低音，不弹窗。

### 6.3 点灯（提示）

点灯不直接给答案，而是**照亮当前档位最低的一处推理**：高亮相关的行/列/宫和候选，写出技巧名（如「第 4 宫中 7 只能在这里」）。玩家照着落子，这一步按 §5.3 记 0 分。教学价值大于惩罚。

## 7. 出题与校验

### 7.1 模块（全部纯函数、确定性）

`src/games/sudoku-mist/model/`：

| 模块 | 职责 |
|---|---|
| `grid.js` | 81 格 + 每格 9 位候选掩码；行/列/宫索引表 |
| `brute.js` | 位运算回溯求解器：唯一解校验、解数计数（上限 2） |
| `techniques.js` | 技巧梯 T1–T4 与推导闭包；每格给出档位、落子技巧、关键技巧（第一次用到该档的技巧）和依据单元，供点灯与回放使用。排除类技巧的完整证据（哪些候选被排除）留到 P1 做点灯 UI 时补 |
| `fog.js` | 可见性、揭雾核（`box` / `cross`）；特殊格留到第三章 |
| `scoring.js` | §5 的档位判定与计分 |
| `generator.js` | 先布雾再挖空（§7.2）、逐格路径模拟、批量可解性判定、每日题 |
| `session.js` | 一局的规则状态机：落子 / 填错 / 揭雾 / 计分 / 点灯 / 通关统计 / 按输入序列回放；只向外暴露知识视图 |
| `levels.js` | 关卡（离线生成后人工挑选，存成字符串） |

随机数一律来自 `src/platform/daily.js` 的 `mulberry32` / `hashString`，不自带 RNG。

### 7.2 生成流程

**先布雾，再挖空**（P0 实测后改定，原方案的问题见 §14）：

1. 用种子生成终盘 S，先把**整个终盘当作题面**、全部藏在雾里，只开一宫。
2. 模拟「按技巧梯推进的玩家」：每步在当前知识下跑 cap 档闭包，取最先推出的格落子 → 揭雾。卡住就在卡住处的雾边缘多开一格视野，直到能走完。
3. 按随机顺序逐格尝试：去掉这个题面数字 / 把这格从开局视野里收回，只要存在带雾可通关路径就保留改动（题面数字不少于 profile 的下限）。这一步用**批量判定**：每轮把闭包推出的格一次性全落下、一起揭雾；它只验证一条充分的可通关路径，任意顺序不死局的保证还需要 §7.3 的手动拨雾权。批量判定让闭包次数少一个数量级。
4. 用逐格路径算最终统计（逐格走不完的题直接作废）：
   - 用到的最高档位；
   - **卡点数**：可推格 ≤ 2 的状态有多少（雾带来的紧张感）；
   - **只能穿雾数**：所有可推格都在雾中的状态有多少。
5. 统计不达标就换下一个种子（确定的种子序列，最多 12 次；仍不达标退回第一道可解的题并标记 `relaxed`）。

带雾路径能走完，就意味着解唯一（每一步都是推理的必然结果）。`brute.js` 只用于校验器交叉核对和运行时求终盘。

### 7.3 「永不卡死」怎么保证

- 所有落子都是对的（填错会退回），所以知识只增不减。
- 旧的「已知信息只增不减，因此存在路径就代表任意顺序可解」证明有漏洞：某个雾中题面数字可能在落子前被另一动作揭开，变成不可落子的已知数字，它原本对应的揭雾机会随之消失。合法推理顺序便可能留下永远解不开的雾。
- 修复：每个**开局藏在雾中、后来被揭开的题面数字**保留一次手动拨雾权，不得自动链式触发。对已找到的通关路径 p₁…pₙ，在另一顺序下重新依次考虑每个 pᵢ：若它仍是未知格，就按原有效推理落子；若它已被提前揭开成为已知题面，就主动触发保存的拨雾权。如此可重建路径中每一步的揭雾集合，不再因为提前揭开而丢掉揭雾来源。已拨雾过的格不会重复触发，初始可见题面不具拨雾权；补救不计分。
- 单数类技巧（T1/T2）严格单调；T3/T4 的单调性不做理论承诺，使用随机玩家机器人做回归验证。每关分别跑 120 条「推理优先、无推理时拨雾」和 120 条「推理与拨雾随机交错」路径；每日题抽样 30 天 × 5 遍 × 两种策略，自由局三档（包含 T4）各 4 个种子 × 10 遍 × 两种策略。审查中的六格迷雾样例另穷举全部 65 个可达状态，断言没有死局。随机测试不是所有 T3/T4 题目的数学证明。

### 7.4 每日题：运行时生成 + 黄金值冻结

- 每日题由 `hashString('sudoku-mist:v<GENERATOR_VERSION>:<todayKey()>')` 做种子，在浏览器内运行时生成（同 Gravity Slingshot），不维护题库文件。
- 风险是生成器一改，已发布的每日题全部变样。对策同 `daily.js` 的哈希冻结规则：生成器带 `GENERATOR_VERSION`；`verify-sudoku-mist-daily` 锁住 5 个固定日期的种子与题面哈希，以及连续 30 天的摘要哈希；改出题算法必须升版本、并显式更新黄金值。
- 性能：Node 下单题生成实测 p50 ≈ 65ms、p95 ≈ 130ms（校验器预算 p95 ≤ 600ms，留足并发余量）。手机可能慢 3–5 倍，P1 用「雾慢慢散开」的开场动画盖住，必要时挪进 Web Worker。

## 8. 模式与关卡

### 8.1 晨雾·关卡

| 章 | 名称 | 新东西 | 档位上限 |
|---|---|---|---|
| 一 | 初雾 | 揭雾本身；`box` 核，雾散得快 | T2 |
| 二 | 穿雾 | `cross` 核；每局平均 8–9 次只能穿雾 | T2 |
| 三 | 灯笼 | 特殊题面格「灯笼」：玩家落子揭开它时点亮整宫（仍由落子触发，不连锁） | T3 |
| 四 | 深雾 | 视野更窄，需要 T3/T4 才能破局 | T4 |

每章 4 关；本地记录每关最高分与星级（星级按该关的推理分阈值）。

### 8.2 每日一雾

- 每天一盘（UTC+8），全球同题，排行榜按推理分降序。
- **每日局不可重开**：进度自动保存，中途离开回来继续；只提交第一次完成的成绩。否则玩家记住雾的布局后重开，分数就失真了。完成后可以无限次练习，但不再提交。
- 完成写 `game:sudoku-mist:v1:daily:<YYYYMMDD>`，供首页每日任务区判断（是否进入每日任务区待定，§13）。

### 8.3 自由局

选档位（初雾 / 穿雾 / 深雾）随机出题，不进排行榜。

### 8.4 晴空模式（可选，第三阶段）

无雾的普通数独，只保留 §5 计分，可以开自动候选（但自动候选下计分关闭）。给不喜欢雾的玩家，也是一个对照组。

## 9. 页面与工程

### 9.1 布局

- 标准 shell（`layout` 不声明），DOM 网格棋盘，参照扫雷与黑白棋：盘面是 81 个 `<button>`，键盘和读屏都靠它。
- **雾是覆盖在 DOM 网格上的 Canvas 层**（`pointer-events: none`），按网格几何对齐；命中测试只走 DOM。雾密度场 = 每格一个值，双线性柔化 + 缓慢漂移的噪声；散雾是密度渐退。
- 移动端：盘面占满宽度，数字键盘在下。按 `docs/mobile-qa-pr135.md` 用可见视口（375×553 / 390×664）验收。
- 桌面 ≥1024px：盘面放大（参照黑白棋 640px），旁边放侧栏：当前分、连推、档位图例。Prototype 阶段先不做 sidebar/drawer cap，HUD 放在舞台内（`stage-status` 约定）。

### 9.2 视觉方向

**宣纸 × 晨雾 × 水墨**。浅色模式是清晨白雾、宣纸底；深色模式是月下蓝雾、灯笼暖光。从第一天起支持 `theme-light`（DOM 棋盘，成本低）。雾和墨的颜色通过 `readPalette()` 从 CSS 变量读取。`prefers-reduced-motion` 下雾静止，散雾改为淡出。

### 9.3 信息隔离（硬约束）

- 终盘 S 与雾中题面只存在于 model 中。runtime 交给渲染层的是**知识视图**：每格 `fog | given(d) | open | placed(d)`，雾中格不带任何数字。
- DOM 文本、`aria-label`、`data-*` 都不得含雾中格内容；读屏对雾中格只读「雾中，未知」。
- `smoke-sudoku-mist` 断言：开局 DOM 中出现的数字 ⊆ 可见格数字。

## 12. 原型要验证的两件事

1. **雾是不是增加了决策，而不只是遮挡**？玩家会不会主动规划「先推哪里能揭开更多」，有没有找到穿雾时的「啊哈」？
2. **推理计分能不能看懂、会不会改变行为**？玩家是否因为「侥幸 0 分」而少猜，是否会去找更高档位的格子？

**止损**：如果试玩反馈是「雾只是烦」，就把雾降为可选模式，以 B（推理计分 + 回放）为核心继续；不要靠堆关卡或加机制来掩盖。

## 14. P0 实现记录（2026-10-18）

**已交付**：`src/games/sudoku-mist/model/`（grid / brute / techniques / fog / scoring / session / generator / levels），选关工具 `tools/generators/sudoku-mist-levels.mjs`，测试用玩家模型 `tests/lib/sudoku-mist-bot.mjs`，三个离线校验器（`verify-sudoku-mist-model` / `-levels` / `-daily`）。页面、registry、排行榜都还没接。

**反向验证**：在副本里注入 6 个变异——闭包不从低档重来、雾中格泄露数字、穿雾不乘倍数、落子不揭雾、区块排除越界、出题参数微调——每个都至少让一个断言变红。

**实测后改掉的设计**：

1. **先挖空、再布雾行不通**。原 §7.2 的做法下，开一宫几乎什么都推不出，出题器平均要补约 22 格视野，最后近九成题面数字开局就可见，每步平均 15 格以上可推，雾形同虚设。改成「先布雾，再挖空」后：开局视野约 11–15 个题面数字，每步平均 5–8 格可推，每局约 11 个卡点。
2. **开局只有数字孤岛**。收完视野后开局没有可见空格，前几步必然是穿雾。试过把可见数字周围的空格也露出来（这些空格不带信息），结果开局近半盘清晰，只能穿雾的状态减半，已放弃。P1 的视觉要让雾中格明显可以点。
3. **新增 `cross` 揭雾核**（见 §4.3）。

**留给 P1 试玩的问题**：

- **计分的策略深度偏浅**。第一、二章 70%–90% 的落子是 T1（宫内隐性唯一 / 唯一空位），贪分玩家只比随机推理玩家高 2%–13%。「越早推出高档位格越值钱」这条策略目前没有多少发挥空间。可调方向：拉开 T1 与 T2 的分差；让穿雾倍数随连续穿雾递增；或者把卡点（只剩 1–2 个可推格）时的落子单独加成。
- **T4 在随机题里极少出现**（隐性三数组在语料里一次都没出现），第四章「深雾」需要专门的出题档位或手工挑题。

## 15. P1 实现记录（2026-10-18）

**已交付**：`sudoku-mist.html` + `css/sudoku-mist.css` + `src/games/sudoku-mist/`（`index.js` / `runtime.js` / `render/board.js` / `render/mist.js` / `audio.js` / `i18n.js` / `storage.js`），`tests/smoke-sudoku-mist.mjs`（35 项真实交互断言）。

**和原计划不同的地方**：

- **P1 就登记进了 registry**（原计划 P2 才接首页）。原因：Vite 构建入口、页头 SEO、站点地图都由 `games.config.json` 派生，不登记就进不了构建；萤火信号原型也是这样做的。所以首页已经有卡片（「新」胶囊，`addedAt` 2026-10-18）、分享图 `public/assets/seo/og-sudoku-mist.svg`、首页图标。caps 只有 `analytics` / `topbar` / `theme-light`，不带 `leaderboard` / `daily`。
- **键盘在舞台外**。冻结后新增的页面只能定义 `--sm-*` 变量、不能调 `--frame-*`，舞台宽度沿用共享默认（最宽 460px）。所以数字键盘放在 `.game-main` 里舞台旁边的独立面板：手机在棋盘下方（6 列 × 2 行：1–5 + 笔记 / 6–9 + 擦除 + 点灯），桌面在棋盘右侧（3×3 数字 + 一行工具）。390×664 可见视口下棋盘、键盘都在首屏内。
- **菜单与结算卡随内容撑高舞台**：菜单期间棋盘只占位不显示（桌面上退出布局），结算期间 HUD 与棋盘退出布局，否则 460px 的舞台会裁掉按钮。

**实现要点**：

- **三层棋盘**：底色 → 雾层 canvas → 格子按钮。网格线、选框、笔记都浮在雾上；雾中格的 DOM 里本来就没有数字，读屏标签只读「雾中，未知」。
- **雾的画法**：每格 3×3 子像素的 27×27 浓度场平滑放大（边缘自然柔化约 1/3 格），叠两层缓慢漂移的噪声当雾丝。揭雾时按与落子格的距离错开 60ms 依次淡出，落子格画一圈涟漪。`prefers-reduced-motion` 下雾丝不动、无涟漪。动画循环只在对局 / 回放且未暂停时运行。
- **输入**：先选格再选数，或先拿起数字再点格；键盘方向键 / 1–9 / Shift+数字或 N 记笔记 / H 点灯 / P、Esc 暂停。
- **笔记**：手动记，不提供自动候选。落子或揭开题面数字后，自动清掉同行列宫里同一数字的笔记——这只是减少记账，不提供新信息。
- **点灯**：按技巧生成说明（「第 8 宫只剩这一格，一定是 6。」）并高亮依据的单元；需要 T3/T4 时附上要先用的技巧名。
- **结算**：分数、各档位次数、穿雾 / 侥幸 / 点灯 / 失误、最长连推、用时。「推理回放」按原输入序列逐步重放（每步 280ms），可随时停止。
- **自由局**：初雾 / 穿雾 / 深雾三档，运行时用随机种子出题。最佳分按关卡与自由局档位分别存在 `game:sudoku-mist:v1:best:<id>`。

**还没做（P2）**：每日一雾页面入口与进行中对局持久化续玩、排行榜、星级、按 §12 组织试玩。当前每日题生成器和输入序列回放已经完成；页面存储范围是关卡 / 自由局最佳通关记录（包括 0 分），不代表已经支持刷新后恢复未完成对局。

## 16. P2 实现记录（2026-10-18）

**已交付**：

- **每日一雾**：菜单顶部一个入口，显示今天（UTC+8）的状态：未开始 / 继续 · 已走 N 步 / 已完成 · 分数。题目由 `generateDaily(todayKey())` 在浏览器里生成，同一天只生成一次。
  - **今天第一次完成之前是计分局**：每次输入（落子、填错、拨雾、点灯、记笔记）后把 `{ seed, inputs, elapsed, notes }` 写进 `game:sudoku-mist:v1:daily-run:<YYYYMMDD>`；暂停、回菜单、切到后台、`pagehide` 也各写一次。再进来时用 `replay(level, inputs)` 原样恢复分数、雾、连推，笔记与用时同时恢复，续玩不重复上报 `play`。`seed` 对不上（生成器升过版本）就丢掉旧进度。
  - **计分局不能重开**：顶栏重开不出现，暂停浮层没有「重新开始」，说明文案改成「已保存，不能重开」。
  - **完成**：写完成标记 `game:sudoku-mist:v1:daily:<YYYYMMDD>` = `{ score, time }`，清掉进度，向 `sudoku-mist-d<YYYYMMDD>` 提交一次（键取这一局自己的日期，跨过午夜不串榜）。0 分也提交。
  - **之后是练习局**：「再来一局」或从菜单再进都从头开始，可以重开，不存进度、不提交；结算显示今天的计分成绩。
  - **PR #160 审查后的边界**：「今天完成过没有」统一走 `dailyDoneFor()`（本地完成标记 + 本页内存兜底），完成那一刻再查一次——同一天两个标签页各开一局，先完成的计分，后完成的自动降为练习局，不覆盖、不重复提交；完成标记写不进存储时进度不清（可恢复），本页内存记住已完成，不会再开计分局；提交用共享 dialog 的 `journal: true`：先把成绩写进本地重试队列 `scoreboard:pending:v1` 再 POST、确认后移除，请求没回来就关页，下次进页（或打开任何排行榜）会补交整个重试队列——跨过午夜的昨日成绩也按它自己的榜单键补交。榜上每人只留最好成绩，重复 POST 无害。
- **排行榜**：共享 `scoreboard-dialog`，只有每日榜一个 board（`scores` 块无全时键，Worker 只认 `DAILY_PATTERNS` 里的 `sudoku-mist-d\d{8}`，`maxScore` 50,000、保留 14 天）。入口：顶栏奖杯（暂停钮左边）+ 每日局结算卡（关卡 / 自由局结算卡上隐藏）。打开时走 `pauseOwnership` 的 `ranking` 租约静默暂停、关闭后继续。
- **星级**（§8.1）：每关 `stars: [★2, ★3]` 分数阈值。阈值由 `tests/lib/sudoku-mist-bot.mjs` 的 `starThresholds()` 算：60 条固定种子的随机推理玩家（不猜、不错、不点灯），★2 = 最差一条的 90%，★3 = 中位数，都向下取整到 10。`tools/generators/sudoku-mist-levels.mjs --write` 写进 `levels.js`（重写后题面与视野逐字不变），`verify-sudoku-mist-levels` ⑦ 复算比对，并断言贪分玩家拿得到 ★3、瞎猜玩家只有 ★1。星数由本地最佳分推出，不另存；只有章节关卡有星。
- **校验**：`smoke-sudoku-mist` 新增 ⑮ 星级、⑯ 每日一雾（真实点击开局 → 进度写入 → 整页刷新续玩 → 排行榜弹窗静默暂停 → 通关只 POST 一次、分数 = Node 侧回放 → 练习局不提交）；`verify-scoreboard-contract` 接受只有每日榜的 dialog 游戏，并锁住「只有计分局提交、按对局日期提交」。反向验证：让练习局也提交、或续玩不按输入序列恢复，smoke 与契约校验都会变红。
