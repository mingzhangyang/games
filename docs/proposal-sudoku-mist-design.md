# 《雾隐九宫 Sudoku in the Mist》设计方案

> 状态：设计提案 · 2026-10-18（未开工）
> 方向：A「迷雾数独」为骨架 + B「推理即得分」为反馈；外观借东方晨雾意象
> 工作名与 id 见 §13，可改

## 1. 一句话定义

一盘标准 9×9 数独，开局被晨雾笼罩；**每一个推理出来的数字都会拨开周围的雾**，露出下一步需要的线索。分数不看快慢，看你每一步**推理得有多深**——猜对的数字不算本事。

## 2. 设计原则

1. **规则零改动**：行、列、宫 1–9 不重复，解唯一。爱好者认的那层不动，特色全部放在「信息、反馈、目标」三层。
2. **雾只藏信息，不撒谎**：雾里是什么，揭开后就是什么；渲染层和 DOM 永远拿不到雾中格的内容（§9.3）。
3. **永不卡死**：任何合法的推进顺序都不会把玩家逼到「只能猜」的局面——由构造保证、由校验器锁住（§7.3）。
4. **奖励看见，不奖励手快**：排名按推理分，时间只展示不排名。
5. 先验证好不好玩，再做美术和产品化（同萤火信号的 Prototype 路线）。

## 3. 核心体验

- **开局**：只有一小片视野（例如一宫加零星几格），其余是雾。你看得见的线索很少，但足以推出第一个数字。
- **推进**：每填对一格，它周围 8 格的雾散开。露出来的可能是新的已知数字，也可能是空格。盘面像晨雾被阳光一点点照透。
- **穿雾**：有时候一个数字推得出来，但它在雾里——比如某行只剩一个空位在雾中。你可以**直接把数字落进雾里**，雾随之破开，这一步额外加分。这是本作最想做出来的「啊哈」时刻。
- **结算**：回放你的整条推理链：哪一步用了什么技巧、哪几步穿了雾、哪一步是侥幸猜的。

## 4. 规则

### 4.1 格子的三种状态

| 状态 | 玩家看到 | 说明 |
|---|---|---|
| 雾中 `fog` | 只有雾 | 不知道它是题面给出的数字还是空格 |
| 可见·题面 `given` | 墨色数字 | 雾散后露出的题面数字 |
| 可见·空格 / 已填 `open` / `placed` | 空格或玩家填的数字 | |

雾中的题面数字与雾中的空格**对玩家完全等价**：都是「未知格」。

### 4.2 落子

- 玩家可以在任何**未确定**的格子落子：可见空格，或雾中格（穿雾）。
- **填对**：数字落定（不可撤销，因为它是对的），触发揭雾（§4.3），按 §5 计分。
- **填错**：立即退回，墨迹晕开一下，扣分并打断连推（§5.3）。错的数字从不留在盘面上——这保证「当前已知信息」永远是真的，§5 的推理判定才有意义。
- 若雾中格其实是题面数字，玩家推出并落下它，同样计分、同样触发揭雾：**先推出来比等它被揭开更值钱**，这是排序策略的一部分。

### 4.3 揭雾

- 每次**落子成功**，以该格为中心的 3×3 邻域（切比雪夫半径 1）全部揭开。
- 被揭开的题面数字**不会**连锁揭雾，只有玩家的落子会。否则开局一串连锁就把雾吹光了。
- 后期章节的特殊格（§8）可以改变揭雾范围，但规则始终是「落子触发、无连锁」。

### 4.4 铅笔标记

- 手动铅笔标记随意用，不影响计分。
- **不提供自动候选数**：自动候选会把最基础的推理（§5 的 T1/T2）直接替玩家做完，与本作的核心反馈冲突。「晴空模式」可以考虑开放（§8.4）。

## 5. 推理即得分

### 5.1 每一步的「推理档位」

玩家落子的那一刻，取**当前知识** K = 所有可见的题面数字 + 已落子数字。雾中格一律视为未知。

用一个模仿人类解题的技巧梯（§7.1）判断这一格：

> 这一格的档位 = 最小的 t，使得「只用 ≤ t 档的技巧，从 K 出发反复推导直到不动点」能确定这一格的值。

找不到任何 t ≤ T4 能确定 → 这一步是**侥幸**（玩家猜对了）。

注意这里取的是推导**闭包**：如果玩家在心里先推了别的格、再推到这一格，仍然按闭包算出它的档位，不吃亏。

### 5.2 档位与基础分

| 档位 | 技巧 | 基础分 |
|---|---|---|
| T1 | 唯一空位（单元只剩一格）、宫内隐性唯一 | 10 |
| T2 | 行/列隐性唯一、唯余数（裸单） | 20 |
| T3 | 区块排除（pointing / claiming）、显性/隐性数对 | 40 |
| T4 | 显性/隐性三数组、X-Wing | 80 |
| — | 侥幸（当前信息推不出） | 0 |

MVP 只到 T4。更高阶技巧（XY-Wing、链）不进出题器，确保题目不需要它们。

### 5.3 乘数与扣分

- **穿雾**：落在雾中格 ×1.5。
- **连推**：连续第 n 次推理落子（非侥幸、非提示）乘 `1 + 0.1 × min(n − 1, 10)`，上限 ×2.0。
- **侥幸**：0 分，连推清零，结算回放里标出。
- **填错**：−20（总分不低于 0），连推清零。
- **提示**（点灯，§6.3）：这一步 0 分，连推清零。

单步分 = `round(基础分 × 穿雾 × 连推)`。

量级估算：一盘约 50–55 次落子；普通玩家多在 T1/T2，约 1,500–2,500 分；理论上限约 55 × 80 × 1.5 × 2 ≈ 13,200。排行榜 `maxScore` 取 50,000 留余量。

### 5.4 这套计分带来的策略

- 高档位格**越早落越值钱**：同一格，等更多信息出现后再填可能只剩 T1。先看出深层推理是被奖励的。
- 穿雾 + 高档位叠乘，是高分的主要来源。
- 暴力试数会被重罚：试错扣分，试对也是侥幸 0 分。

## 6. 操作

### 6.1 输入

- **先选格再选数**（默认）和**先选数再点格**两种方式都支持；先选数时高亮盘面上所有该数字及其行列宫。
- 手机：盘面下方 1–9 数字键 + 铅笔切换 + 擦除（只擦铅笔）+ 点灯。数字键 ≥44px。
- 键盘：方向键移动、`1–9` 落子、`Shift+1–9` 或 `N` 切换铅笔、`Backspace` 擦铅笔、`H` 点灯、`P`/`Esc` 暂停（站点惯例）。
- 雾中格**可以被选中**（穿雾需要），选中时只显示选框，不泄露任何内容。

### 6.2 反馈

- 落子成功：数字墨迹落定 → 邻域雾在约 600ms 内散开；浮字显示 `+40 区块 ×1.5 穿雾`。
- 档位用**文字缩写 + 颜色**双编码（色盲友好），不只用颜色。
- 填错：墨迹晕开退回，短促低音，不弹窗。

### 6.3 点灯（提示）

点灯不直接给答案，而是**照亮当前档位最低的一处推理**：高亮相关的行/列/宫和候选，写出技巧名（如「第 4 宫中 7 只能在这里」）。玩家照着落子，这一步按 §5.3 记 0 分。教学价值大于惩罚。

## 7. 出题与校验

### 7.1 模块（全部纯函数、确定性）

`src/games/sudoku-mist/model/`：

| 模块 | 职责 |
|---|---|
| `grid.js` | 81 格 + 每格 9 位候选掩码；行/列/宫索引表 |
| `brute.js` | 位运算回溯求解器：唯一解校验、解数计数（上限 2） |
| `techniques.js` | 技巧梯 T1–T4，每条技巧返回推导结果 + **证据**（哪个单元、哪些候选），供点灯与回放使用 |
| `fog.js` | 可见性、揭雾核、特殊格 |
| `scoring.js` | §5 的档位判定与计分 |
| `generator.js` | 生成终盘 → 挖题面 → 布雾 → 路径校验 → 修补（§7.2） |
| `levels.js` | 关卡（离线生成后人工挑选，存成字符串） |

随机数一律来自 `src/platform/daily.js` 的 `mulberry32` / `hashString`，不自带 RNG。

### 7.2 生成流程

1. 用种子生成终盘 S。
2. 挖空得到题面 G，`brute.js` 保证唯一解。
3. 选初始视野 V0（按章节模板：一宫、十字、散点等）。
4. 模拟「按技巧梯推进的玩家」：在当前知识下找所有可推格 → 落子 → 揭雾，直到解完。记录路径和统计：
   - 用到的最高档位；
   - **瓶颈数**：可推格 ≤ 2 的状态有多少（雾带来的紧张感）；
   - **穿雾必要数**：所有可推格都在雾中的状态有多少（第二章要求 ≥ k）。
5. 卡住或统计不达标 → 修补：补一个题面数字、扩视野或换种子重来。设置迭代上限。

### 7.3 「永不卡死」怎么保证

- 所有落子都是对的（填错会退回），所以知识只增不减。
- 设出题器找到的路径为 p₁…pₙ。对任意可达状态，取 p 中第一个尚未落子的 pᵢ：p₁…pᵢ₋₁ 都已落子，它们触发的揭雾也都发生了，当前知识 ⊇ 路径上那一刻的知识。只要技巧梯对「信息更多」单调（多知道一些，原本推得出的格仍推得出），pᵢ 现在就一定可推。
- 单数类技巧（T1/T2）严格单调；T3/T4 的单调性不做理论承诺，交给随机玩家机器人兜底：每关跑数百条随机合法顺序，断言从未卡死（同萤火信号的 solver bot 做法）。

### 7.4 每日题：运行时生成 + 黄金值冻结

- 每日题由 `hashString(dailyKey('sudoku-mist'))` 做种子，在浏览器内运行时生成（同 Gravity Slingshot），不维护题库文件。
- 风险是生成器一改，已发布的每日题全部变样。对策同 `daily.js` 的哈希冻结规则：生成器带 `GENERATOR_VERSION`；`verify-sudoku-mist-daily` 锁住固定日期集合的题面哈希；改出题算法必须升版本、并显式更新黄金值。
- 性能预算：Node 下单题生成 p95 < 200ms；超时就换种子重试，次数有上限，保证一定出题。

## 8. 模式与关卡

### 8.1 晨雾·关卡

| 章 | 名称 | 新东西 | 档位上限 |
|---|---|---|---|
| 一 | 初雾 | 揭雾本身；视野宽，瓶颈少 | T2 |
| 二 | 穿雾 | 路径必须穿雾（穿雾必要数 ≥ 2） | T2 |
| 三 | 灯笼 | 特殊题面格「灯笼」：被揭开时点亮整宫 | T3 |
| 四 | 深雾 | 视野更窄，需要 T3/T4 才能破局 | T4 |

每章 4 关；本地记录每关最高分与星级（星级按该关的推理分阈值）。

### 8.2 每日一雾

- 每天一盘（UTC+8），全球同题，排行榜按推理分降序。
- **每日局不可重开**：进度自动保存，中途离开回来继续；只提交第一次完成的成绩。否则玩家记住雾的布局后重开，分数就失真了。完成后可以无限次练习，但不再提交。
- 完成写 `game:sudoku-mist:v1:daily:<YYYYMMDD>`，供首页每日任务区判断（是否进入每日任务区待定，§13）。

### 8.3 自由局

选档位（初雾 / 穿雾 / 深雾）随机出题，不进排行榜。

### 8.4 晴空模式（可选，第三阶段）

无雾的普通数独，只保留 §5 计分，可以开自动候选（但自动候选下计分关闭）。给不喜欢雾的玩家，也是一个对照组。

## 9. 页面与工程

### 9.1 布局

- 标准 shell（`layout` 不声明），DOM 网格棋盘，参照扫雷与黑白棋：盘面是 81 个 `<button>`，键盘和读屏都靠它。
- **雾是覆盖在 DOM 网格上的 Canvas 层**（`pointer-events: none`），按网格几何对齐；命中测试只走 DOM。雾密度场 = 每格一个值，双线性柔化 + 缓慢漂移的噪声；散雾是密度渐退。
- 移动端：盘面占满宽度，数字键盘在下。按 `docs/mobile-qa-pr135.md` 用可见视口（375×553 / 390×664）验收。
- 桌面 ≥1024px：盘面放大（参照黑白棋 640px），旁边放侧栏：当前分、连推、档位图例。Prototype 阶段先不做 sidebar/drawer cap，HUD 放在舞台内（`stage-status` 约定）。

### 9.2 视觉方向

**宣纸 × 晨雾 × 水墨**。浅色模式是清晨白雾、宣纸底；深色模式是月下蓝雾、灯笼暖光。从第一天起支持 `theme-light`（DOM 棋盘，成本低）。雾和墨的颜色通过 `readPalette()` 从 CSS 变量读取。`prefers-reduced-motion` 下雾静止，散雾改为淡出。

### 9.3 信息隔离（硬约束）

- 终盘 S 与雾中题面只存在于 model 中。runtime 交给渲染层的是**知识视图**：每格 `fog | given(d) | open | placed(d)`，雾中格不带任何数字。
- DOM 文本、`aria-label`、`data-*` 都不得含雾中格内容；读屏对雾中格只读「雾中，未知」。
- `smoke-sudoku-mist` 断言：开局 DOM 中出现的数字 ⊆ 可见格数字。

## 10. 校验

| 校验器 | 类型 | 锁住什么 |
|---|---|---|
| `verify-sudoku-mist-model.mjs` | 离线 | 技巧梯用已知题例做单测（每条技巧有正例和反例）；揭雾规则；计分公式；同种子同输入同结果 |
| `verify-sudoku-mist-levels.mjs` | 离线 | 每关：唯一解、路径可解、档位上限、章节统计阈值；随机玩家机器人（`tests/lib/sudoku-mist-bot.mjs`）数百条顺序永不卡死；理想玩家得分 > 随机推理玩家 > 暴力试数玩家 |
| `verify-sudoku-mist-daily.mjs` | 离线 | 固定日期集合的题面哈希黄金值；生成耗时预算；连续 365 天都能出题 |
| `smoke-sudoku-mist.mjs` | 浏览器 | 真实点击和触摸：落对 → 雾层像素变化；落错 → 退回且扣分；穿雾；完成 → 结算分数与 model 一致；雾中信息不泄露（§9.3）；暂停与切到后台；中英文；浅色/深色；移动端视口 |

离线项自动进入 `verify:quick`。动手前先过一遍 `docs/traps.md` 的「结算渲染 / 按钮图标 / 校验基础设施」三节。

## 11. 分阶段

| 阶段 | 内容 | 出口 |
|---|---|---|
| P0 模型 | `model/` 全部 + 三个离线校验器 + 第一、二章 8 关候选 | 校验全绿；出题器能稳定产出达标的穿雾关 |
| P1 可玩原型 | 页面、输入、雾层（程序化）、计分浮字、结算回放、自由局；不接排行榜 | 试玩验证（§12） |
| P2 产品化 | 每日一雾 + 排行榜 + 首页卡片 + OG/封面 + smoke 全覆盖 | `npm run verify` 全绿 |
| P3 扩展 | 第三、四章（灯笼、深雾）、晴空模式、美术分层素材 | 视需要 |

## 12. 原型要验证的两件事

1. **雾是不是增加了决策，而不只是遮挡**？玩家会不会主动规划「先推哪里能揭开更多」，有没有找到穿雾时的「啊哈」？
2. **推理计分能不能看懂、会不会改变行为**？玩家是否因为「侥幸 0 分」而少猜，是否会去找更高档位的格子？

**止损**：如果试玩反馈是「雾只是烦」，就把雾降为可选模式，以 B（推理计分 + 回放）为核心继续；不要靠堆关卡或加机制来掩盖。

## 13. 待你拍板

1. **名字**：工作名「雾隐九宫 / Sudoku in the Mist」，id `sudoku-mist`，前缀 `sm`。
2. **要不要失败条件**：本方案没有「错三次结束」，填错只扣分。如果想要紧张感，可加「三盏灯」硬核选项。
3. **首页每日任务区**：现在固定 3 项；数独加入会变成 4 项，需要连带改首页。也可以只挂 `daily` 胶囊、不进任务区。
4. **晴空模式**是否要进 MVP。
5. **美术**：P1 用程序化雾和宣纸底；是否在 P3 约分层美术素材（同萤火信号、影织）。
