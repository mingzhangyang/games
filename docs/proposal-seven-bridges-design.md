# 七桥漫游 Seven Bridges 完整实现方案

> 状态：完整实现方案，尚未实现或发布。
> 日期：2026-10-12 · 设计版本：1.0 · 名称为工作名。

共同方向、平台集成、交付批次与数学来源见 [两款图论游戏交付方案](proposal-graph-puzzles-delivery.md)。

## 1 产品定位与第一分钟

**一句话：**在河港中走遍每座桥，把城市看成一张关系图，再亲手改建那些无法完成的旅程。

首屏是一座有纸雕质感的微缩水城。玩家的小小信使站在岸边；点击一座相邻桥，信使走过去，桥灯点亮。第一关用极少分岔教会“每桥一次”；第二关出现两个环与一座连接桥，玩家第一次意识到“能走过去，不等于现在该过去”。

正式首发目标为 **32 个主线关，包含 1 个明确的历史发现关；另有 8 个工程委托、每日漫游与路线明信片**。普通路线关目标 1—4 分钟，修桥关约 3—8 分钟。世界有轻叙事：从陌生旅人逐渐成为能读懂和改善城市的规划者。

## 2 核心规则与完成判定

- 桥是无向边，陆地是顶点；可以多次回到同一陆地，每座必经桥只能走一次。不能游泳、跳跃或通过背景装饰跨越陆地。
- 普通漫游允许起终点不同；归港关明确要求回到出发点。起点可以由玩家选，也可以由关卡固定，界面要事先说明。
- 同一对陆地之间可有多座桥，每座桥有独立 ID、命中区和使用状态；不能把它们合并成一条边。
- 玩家抬手后保留路线。所谓“一笔”指路线在逻辑上连续，不要求手指一直按住屏幕。
- 无路可走时保留现场，标出未经过的桥，提供撤销和从其他起点重来；不扣生命、不播放夸张失败遮罩。

| 关卡类型 | 完成条件 | 附加约束 |
| --- | --- | --- |
| 漫游 | 全部必经桥恰好一次 | 尊重固定起点和固定终点 |
| 归港 | 全部必经桥恰好一次并回到起点 | 连通、全部相关顶点偶数度 |
| 历史发现 | 标识原图四个奇数度陆地并完成配对解释 | 不是“走完七桥”；允许一开始就进入解释，不强迫重复失败 |
| 工程委托 | 合法改建后，再亲自完成指定路线 | 建设预算、保护桥、候选位置和是否归港均显示 |

历史关的发现记录与普通通关分开存储；测试不得通过“usedEdges 等于 7”来让原图假通关。所有涉及边的顶点必须处于同一个可遍历连通部分，奇偶数合格但分成两个孤岛的图仍不能通过。

## 3 标志体验 城市变成图

界面边缘有一个“看关系”镜片按钮。按下后，河流与建筑降低存在感，每块陆地的活动中心成为一个点，每座桥化成一条柔和曲线。路线、选中桥、信使位置保持连续映射；再按一次回到城市。

变形约 450ms，减少动态时直接切换。两种视图共用同一个图模型、edgeId 和输入命令，不能是两份独立游戏。每座桥保留双端与曲线信息；动画中暂停新的移动输入并显示短暂过渡状态，完成、取消或切后台后统一解除，不能因丢失 transitionend 卡死。

“看关系”本身不算提示，玩家可以随时切换。主动开启连接计数、奇数度高亮或推荐起点才属于辅助。图景切换要帮助看清结构，但不能自动给出整条路线。

## 4 标志玩法 修桥后走通

工程模式只提供经过美术审核的建设槽位与可拆桥，不允许任意在水面乱画。玩家先在蓝图层加桥或拆桥，旁边实时显示预算使用；确认后城市中的实体桥出现或移除，随后亲自走完路线。

- 首发只支持新增和拆除，不加入桥梁方向、钥匙、传送门、涨潮、移动桥等第二套规则。
- 改建成本按最终相对初始图的差异计算：新增与拆除各一份成本；撤销草稿不累计罚分。每关可定义不同成本，但首发统一单位成本。
- 固定保护桥不可拆；至少保留一座必经桥；每块标记为服务区的陆地都必须被最终路线访问，避免通过删光桥或孤立区域投机通关。
- 进入路线后如要修改工程，明确提示会清空当前路线，保留蓝图。撤销行走与撤销建设分属不同阶段，按钮文字随阶段改变。
- 最小成本作为可选工程印章，只在离线穷举证明后展示。先完成可行方案，再追求更少改建。

这样，七桥问题的无解不是一次性科普结尾，而是游戏后半部的起点：玩家学会判断，再学会改变导致无解的结构。

## 5 四章与工程内容编排

| 章节 | 关卡 | 城市变化 | 核心思考 | 高潮 |
| --- | --- | --- | --- | --- |
| 晨港散步 | 01—08 | 小渔港、晨雾、木桥 | 边不重复、陆地可重复、选择出发点 | 两个环之间的连接桥 |
| 岔路与归途 | 09—16 | 集市、双桥、运河 | 开放路线与归港路线；不能过早离开未走完的片区 | 多个回路拼成一条完整路线 |
| 七桥之城 | 17—24 | 历史水城的艺术化重构 | 城市变图、奇偶配对、固定起终点 | 第 24 关发现原版七桥无解 |
| 给城市一条新路 | 25—32 | 蓝图、施工、灯火归港 | 补桥、拆桥、连通性与预算 | 让七桥变成可归港的九桥之城 |

每章 8 关，后期一般 6—10 块陆地、10—18 座桥；工程委托最多 12 块陆地、24 座桥。手机关卡不把几十座挤在一起的桥当作高难度。8 个工程委托分为 3 个开放路线、3 个归港、2 个连通性陷阱；所有候选工程需几何可读。

章节地图展示解锁城市和路线收藏；无需刷满印章才能进入新章。卡关时允许稍后处理并进入同章其他已开放关，保留当前路线。历史发现关可以通过理解完成，不设强制尝试次数。

## 6 三个关键关卡的精确构造

### SB08 两座广场

左环 A—B—C—A，右环 D—E—F—D，中间只有 C—D 一座连接桥。C、D 为两个奇数度点，玩家应从其中一个出发。若从 C 一开始就过 C—D，左环仍未访问且无法返回；正确路径示例为 C—A—B—C—D—E—F—D。此关把“不要提前切断回头路”变成看得见的体验。

### SB24 原版七桥

```text
陆地：A 中央岛，B 北岸，C 南岸，D 东岛
桥：AB1、AB2、AC1、AC2、AD、BD、CD
度数：A=5，B=3，C=3，D=3
```

玩家可以自由尝试，也可直接使用镜片观察。解释动画把每块中途陆地上的“进入”和“离开”桥两两配对；四个陆地各剩一个端头，而一次连续旅程只有起点与终点两个位置可容纳这样的剩余。玩家点出四个剩余端头，完成发现。并非要求玩家背诵欧拉定理。

### SB25 一座新桥 与 SB32 灯火归港

SB25 在上述原图增加 BC1，度数成为 A=5、B=4、C=4、D=3；可从 A 出发到 D 结束。SB32 在原图同时增加 BC1、AD2，让全部顶点为偶数度，再从 A 走完所有九桥回到 A。建设候选不止正确答案一个；原图桥标为受保护，避免拆桥取巧。

```text
SB25 见证：A → B → A → C → B → D → C → A → D
使用桥序：AB1, AB2, AC1, BC1, BD, CD, AC2, AD

SB32 见证：A → B → A → C → B → D → C → A → D → A
使用桥序：AB1, AB2, AC1, BC1, BD, CD, AC2, AD, AD2
```

开放路线至少需一项新增，归港至少需两项新增：一座新桥最多改变两个顶点的奇偶性，原图有四个奇数度顶点。几何上是否有合适桥位，由艺术化地图布局和候选槽位提供；不能把拓扑可解等同于任意现实河道都能施工。

## 7 交互规则与输入精度

点击桥是默认操作，拖动是熟练玩家的快捷方式。只接受与当前陆地相接、尚未使用的桥。点击远处桥时显示“先走到它的一端”，不偷偷寻路过去。拖动需要进入桥的起点门户、穿过桥廊并进入另一端门户才提交；移动事件稀疏时做线段扫掠检测，不能只检查最后一个采样点。

跨桥后逻辑位置立即到达终点，信使动画随后追上。动画期间允许最多缓存 1 个下一步意图，提交前按当前状态重新验证；更远的点击不堆积成长队。撤销清除动画和缓冲，直接恢复上一个逻辑点与桥状态。点击和拖动共用提交函数，同一 pointer 序列只允许一种提交来源，避免 pointerup 后 click 再走一次。

多桥并行时，桥廊间距与入口必须可区分；靠得太近就打开两张桥选择卡，而不是凭最近距离猜测。桥的可见宽度可小于热区，但重叠热区必须显式消歧。支撑键盘 Tab/方向选择当前可走桥，Enter 前进；屏幕阅读器可听到桥名、目的地和是否已走。

pointercancel、松手、手指移出舞台都只取消未提交的一段，不清空已有路线。只有舞台区域使用必要的 touch-action，设置页面仍可正常滚动。横屏使用同一拓扑的独立排布，不能因旋转重新生成桥或清零进度。

## 8 提示 结算与分享

主线不会默认在每一步告诉玩家哪座桥危险。普通状态只报告直接事实：该桥已走、当前无路、还剩几桥。提示第一层显示未经过的连通片，第二层解释某个选择会把剩余桥留在身后，第三层才给一个可行下一步。提示根据当前剩余图计算，不照抄初始答案。

如果当前路线已不可完成，提示可以建议撤回到一个确切分岔，而不是给出不存在的下一步。用户可按住查看回放，再选择“撤回到这里”；该操作是连续撤销，不重写已经保存的独立完成记录。

主线以完成印章为主，不比较“走了多少步”，因为合法路线必须覆盖相同数量的桥。工程委托记录可行方案成本与经证明的最优成本；独立完成和辅助完成分别保存。历史发现授予一枚“读懂城市”印章，不伪装成走通七桥。

完成后镜头轻退，沿整条路线亮灯，城市倒影安静呈现，约 1.5 秒内出现下一关入口。明信片默认不显示完整路径，以保护每日答案；“展示我的路线”由玩家主动选择。分享失败或平台不支持时提供本地下载，不自动上传照片或路线。

## 9 美术与声景

采用固定镜头的 2.5D 微缩水城：地形与桥面以矢量几何为基础，建筑像小纸模，河流与阴影建立空间。不是写实 3D，也不是把节点涂成圆球。白天水蓝、夜晚靛青，已走桥的灯火温暖；远景节制，桥梁始终比装饰更清楚。

| 层 | 内容与限制 |
| --- | --- |
| 背景 | 天空色、河道、远景纹理，非交互；无网络也能显示矢量 fallback。 |
| 地形与桥 | 同一图数据导出的 SVG 形状；每座桥独立 ID；不使用假交叉口。 |
| 建筑与信使 | 建筑避开桥头和热点；信使沿桥路径移动；两种视图保持位置对应。 |
| 关系层 | 节点、边、选中路线、辅助计数；奇偶提示不仅靠颜色，还用成对短线与落单端头。 |
| 界面 | 顶部轻量导航；底部撤销、镜片、提示；工程阶段替换成建设工具与预算。 |

首发交付 4 套城区氛围、3 类桥材质、12—16 个建筑变体、1 个信使与短动作、8 枚工程印章、首页封面和 OG 图。水面不必常驻全屏滤镜；可用小幅离散纹理变化或短时动画。声音以脚步、木桥、铃声与轻水声构成，走不同桥仅微调音色，不把音高当通关线索。

## 10 图模型 求解器与内容管线

```text
src/games/seven-bridges/
  index.js / game.js
  model/{graph,rules,commands,euler,repair}.js
  content/{levels,chapters,daily-manifest}.js
  render/{city,graph-view,morph,traveler}.js
  input/{pointer,bridge-hit-test,keyboard}.js
  services/{hints,replay,export}.js
  storage.js / i18n.js / audio.js
tools/generators/seven-bridges-build.mjs
tests/verify-seven-bridges-{rules,levels,repair,daily}.mjs
tests/smoke-seven-bridges.mjs
```

**模型：**`nodes[{id}], edges[{id,u,v}], requiredNodes, protectedEdges, candidateEdits, objective, fixedStart, fixedEnd`；坐标、桥廊、桥头、建筑和移动端布局属于 geometry/art，不进入规则判断。首发支持平行边，不开放自环；装饰步道不算边。图视图中曲线交叉也不自动成为节点。

欧拉可行性先检查相关连通性，再检查度数与起终点：0 个奇点可构成回路；2 个奇点时开放路径必须从其中一个到另一个。对于当前残余图，当前位置必须还能进入剩余边，并满足固定终点、归港目标和剩余奇偶条件。无剩余边时单独检查终点，不把当前位置度数为 0 错判为失败。

使用 Hierholzer 算法构造见证路线，结果由独立的逐 edgeId 回放验证器检查。桥割边提示需要支持多重图：DFS 父关系记录 parentEdgeId，而非只记录 parentNode，否则两座平行桥会被错误视为割边。数据规模很小，也可逐候选边移除后做连通性检查，优先可读与正确。

工程求解按候选编辑集合枚举，首发单关候选上限 12、预算上限 3；每个最终图检查预算、保护桥、服务区、连通性与目标奇偶性，再生成路线见证。相同编辑不重复、增删不可相互抵消刷奖励。按总成本递增穷举得到最小成本；搜索中断只报告未知，不写“最优”。

生成流程是“图结构→见证与难度检查→空间嵌入→热点可读性→人工精选”。随机把桥画满河道，再仅靠求解器筛选，会产出大量难看或无思考价值的关卡，不能作为首发内容流程。

## 11 状态 存档与跨视图一致性

页面状态包括 `chapter-map, planning, walking, stuck, discovery, complete`；`city/graph` 是独立展示状态。记录 `levelRevision, finalEditSet, startNode, currentNode, walkedEdgeIds, history, assistance`。visitedEdges 与当前位置必须能由起点和路径重建，读档时校验重建结果；不能同时相信两份互相矛盾的状态。

一次行走提交一个命令；一次工程确认提交一份完整最终编辑集合。游戏在后台暂停声景、计时和动画；回前台直接从模型恢复信使位置，不补跑隐藏期间的脚步。开帮助不消耗路线资源。完成事件有 runId 防重入，重复回放不重复解锁或盖章。

存档使用单快照和 GameStorage.trySet。每天固定一个漫游题，周末固定一个工程题，均来自至少 60 天的离线审核清单；日期与 revision 在开始时冻结。每日不要求首次尝试才算完成，使用提示如实标记，重置不能洗掉同一次挑战的辅助事实。

## 12 验收重点

| 门槛 | 验收方式 |
| --- | --- |
| 历史与规则 | 原版七桥不可行；加一桥开放路径、加两桥归港的见证有效；无解发现关有独立完成条件。 |
| 图边界情况 | 平行桥、两个互不连通的偶数环、错误固定起点、固定终点、最后一步、删桥孤立服务区、全部删空均覆盖。 |
| 输入与动画 | 快速连点不越桥；拖动不漏桥、不双提交；松手不清路线；切图、撤销、旋转、切后台不改变逻辑图。 |
| 工程质量 | 所有关有合法编辑与路线见证；宣称最小成本的关卡完成独立枚举验证；候选桥位无交互歧义。 |
| 理解与乐趣 | 5 位试玩者中 4 位在首关理解桥不能重复但陆地能重访；至少 3 位在七桥章后能用自己的话解释无解原因。 |
| 标志体验 | 城市变图时玩家能追踪当前陆地与桥；工程确认后能理解改变了什么，而不是只看“可以通关”提示。 |
| 性能目标 | 输入提交模型预算 <8ms；仅行走/切图等短窗口运行 rAF；大图无持续布局抖动。按真实设备测量并记录。 |
