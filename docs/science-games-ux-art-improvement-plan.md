# 科学游戏 UI/UX 与美术修复优化方案

日期：2026-10-20。基线：main `c352767`，实施前须核对最新 main。

## 目标与交付

把科学类游戏完善为可亲手操作的科学展品：操作区域清楚、手机可读可点、动作结果可解释，实验对象具有独立的材质与视觉身份。保持现有现代科学展柜的克制界面。

本轮覆盖首页 science 分类的九款游戏。由一名 GPT 6.1 sol 子代理负责实施，主代理独立复核；先完成《焰语》样板，再逐款推进。提交方案、实现、必要回归测试和逐款验收记录，集中推送并创建独立 PR，不直接合并或发布。

此前判断来自代码与资源审阅，尚未完成浏览器基线验收。任何“风险”只有重现后才记为已确认缺陷；不得把设计建议写成已存在的 bug。

## 不变量

- 不改变物理/化学模型、关卡、求解器、胜负条件、成本、par、星级、每日题、排行榜和存档语义。
- 新旧输入渠道调用同一个游戏动作入口；视图读模型状态，不维护第二份配方、预算或进度。
- 不增加自动解题、未付费扫描信息、未探索地图或隐藏答案泄露；辅助反馈只解释当前可见状态。
- 规则几何与显示/命中坐标共用映射。装饰不得伪造可操作区域或改变判定形状。
- 遵守 docs/contracts 的布局、主题、chrome、CSS layer 和组件归属；不复制共享组件、不靠 !important 叠补丁。
- 保持现有中英文与已支持的明暗主题，不顺带扩张主题支持范围。
- 暂停、后台、弹窗、重来、每日切换、重复输入及完成上报保持既有生命周期。
- 不为新的 UI 保留已失效的旧 Canvas 控件/命中路径；迁移完应删除重复路径。
- 不加入无关重构、依赖升级、线上部署或 CI 重跑。

## 第一阶段：基线与问题定位

1. 读现行契约、各款模型/输入/渲染与相关测试，确认行为真源。
2. 恢复真实浏览器环境（参考 docs/browser-testing-environment.md），截图并操作 320×568、390×844、844×390、1280×800。
3. 逐款记录：可用舞台尺寸、文字可读性、控件热区/遮挡、首步引导、错误/完成反馈、资源与主题状态。
4. 区分已证实问题与设计改进，不根据早期提案臆测当前玩法。

## 第二阶段：《焰语》完整样板

### UI 与输入

- 火焰与光谱继续由真实配方驱动；目标/实验光谱对齐，保持同一波长尺度。
- 试剂选择、当前剂量、必要状态读数及动作按钮迁出随 Canvas 缩小的控件区，进入响应式 DOM；手机试剂区采用至少两行，保持有效触摸目标约 44px。
- 选择试剂只选择，明确“加入一份”的成本，提交才调用原投放动作。保留键盘的正确语义与单次计费。
- 提供选中态、满量/不可操作态与可读的反馈。不得根据目标配方直接暴露答案。
- 谱线密集处采用受控局部查看或清楚的读数辅助；不能为了可见而偷偷改变波长数据。若该项涉及较大新增机制，可在验收记录中列为后续，核心布局必须完成。
- 完成、失败、倒掉重来、菜单/每日切换后，DOM 选择/剂量/禁用态必须和模型同步。

### 美术

- 改善燃烧器、观察窗、试剂器物和光谱呈现；实验现象是视觉主角，装饰不挤占读数。
- 原有代码/矢量资产能准确表达器物时直接增强；若需要新增栅格环境素材，使用 imagegen 技能与工具，记录用途及来源，不用占位图交付。
- 按实际需求拆分可复用素材，不把整张概念稿塞成游戏背景，不让生成图片承载文字/精确光谱。

## 美术与架构纪律

1. 环境层负责气氛；器物层负责可识别与操作；现象层直接读取模型。
2. 灯光主要属于光、火、晶体和回声；文本/按钮不新增泛滥霓虹。
3. 避免把大型 runtime 继续堆长；必要时提取专属 view/render/input 模块，保持依赖向下。只在确有多个相同消费者时抽共享层。
4. 热区可比可见物体大，但不重叠、不遮挡其他动作；关键功能不能只靠 hover 或颜色。
5. 减少动态效果时保留状态反馈；无声仍能游玩；无新增外部字体/资源运行时依赖。
6. 新图片按尺寸用途压缩并惰性加载，资源失败时不阻塞游戏；不让本轮显著扩大无关游戏入口。

## 验收与交付标准

- 功能：九款原有模型/关卡 verifier 通过；变更游戏 smoke 通过；新交互验证真实点击/触摸/键盘、单次计费、状态切换与完成路径。
- 布局：上述四种视口，中英文本及支持的主题；无横向溢出、按钮遮挡、关键文字缩成不可读；手机横竖屏切换不丢状态。
- 可玩性：截图检查实际像素，elementFromPoint/真实输入检查点击到的对象；不要只测 DOM 存在。
- 平台：涉及共享布局/样式时验证 chrome、footer、frame-budget、主题和未修改消费者；既有校验不得削弱或豁免。
- 工程：lint、build、仓库要求的 verify 完成；必要时按实际风险补少量回归测试，不测试实现细节。
- 若遇环境/外网失败，记录原命令、失败范围和诊断，不虚报全绿，不通过删除断言解决。
- 逐款记录改动、验证结果、尚未实施的较大增强；附有代表性的前后截图位置/证据。
- 本地提交，集中推送一次；独立 PR 清楚说明动机、实际范围、测试和限制。CI 容量紧张，不循环触发。

## 实施记录

### 实施范围（2026-10-20）

基线已核对 `origin/main=c352767`，独立分支 `feature/science-games-ux-art`。本轮美术以程序绘制、CSS 试剂器物、状态纹理及交互反馈为主；没有新增栅格贴图或依赖，也没有把概念 HTML 移入正式代码。

九款基线在 320×568、390×844、844×390、1280×800 共 36 个视图均无横向溢出。确定的主要缺口是焰语盐架、涟漪相位控件与图表文字随整个 Canvas 缩小；不能把“没有横向滚动”当成可读可点。实现中曾出现新控制台与 Canvas 横排，已改为 `@layer pages` 纵向排列，并增加面板边界与 `elementFromPoint` 断言，避免溢出裁切掩盖问题。

### 全量门禁发现的基线问题

首次冻结后的全量 137 项中，136 项通过，唯一失败是 Tetris 360×640 的棋盘底边 567.80 超过固定底栏顶边 564。只读 `c352767` 基线同样失败；当前分支与基线在 320–390px 的几何逐项一致，`document.fonts.ready` 前后也一致，排除了本轮科学游戏与字体加载时序。

英文初始 HUD 在 360–366px 换两行；分数 999999/等级 99 后，中英文 360–390px 都可能换两行。原样式仅 ≤340px 用 154px 预留，其他手机用 140px，遗漏实际双行范围。经主代理批准，单独提交将原 154px 预留扩展到既有 ≤480px 手机档，并为本地得分标签加 `nowrap`，避免 320px 大数字时「得分」拆成两行；不改共享 JS、测试断言或玩法。原 Tetris 测试新增 320/341/360/366/374/390/480 × 双语的大数字回归，检查棋盘不被底栏遮挡、HUD 无横向溢出。基线定位证据在 `../review/tetris-baseline.log`、`tetris-metrics.jsonl`、`tetris-boundary.jsonl`。
