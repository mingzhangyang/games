# 踩坑日志（traps）

> 这里只放**事故复盘**：一个具体的旧 bug、它为什么没被现有检查抓到、以及守住它的回归脚本。
> 现行规则与参数在 `docs/contracts/`，日常速查在 `CLAUDE.md`；三者不重复。
> 新踩的坑写到这里，不要再追加进 `CLAUDE.md` —— 那里曾经积到 44 KB 的流水账。

---

## 布局与层叠

- ⚠️ Never move a stage's decorative background onto an absolutely-positioned `::before`/`::after` without giving it `z-index: -1` inside an isolated stacking context (`isolation: isolate` on the host). An abspos pseudo-element paints **above** a non-positioned `<canvas>` child — it hides everything the canvas draws *and* swallows every pointer event, so the game becomes unplayable while all geometry checkers still pass. This is how gomoku broke in `566dd8f` (wood board moved from `.board-container`'s background to `::before`). Geometry-only audits cannot catch it: assert on the canvas bitmap pixel + `document.elementFromPoint()` + a real click-driven move — `node scripts/verify-gomoku.mjs`. The migration script's `ROLE_SPECS["stage"]` therefore no longer strips `position` (a redundant `position: relative` is harmless; losing it is not)

- ⚠️ **`aspect-ratio` is silently inert whenever both axes are already definite.** `.game-stage` supplies `width: 100%`, so any page rule that also sets `height` kills the ratio and the canvas gets stretched to whatever box results — no warning, no console message, and every geometry checker that only looks at widths stays green. This bit twice in the same file family: `.sf-stage { height: 640px }` squashed sword-flight on **every phone** (374×640 where 374×499 was correct), and after that was fixed the landscape rule `height: min(640px, calc(100vh - 72px))` did the same thing to na *and* sf in landscape (measured 844×390: ratio 1.51 vs the logical 0.75). When you size a fixed-aspect stage by height, you must also write `width: auto` (plus `max-width: 100%`) so the ratio drives the other axis. Regression: `verify-desktop-frame.mjs` asserts `|w/h − ratio| < 0.01`; extend it to landscape viewports when touching these rules.

- ⚠️ **A shared-layer rule that changes two properties at once cannot be made opt-in by a `var()` fallback, so it must be gated by a body class.** Every other rule in the desktop block degrades on its own (`max-width: var(--frame-shell-max, var(--frame-max-wide))`), but the sidebar cap sets *both* `max-height` and `overflow-y`. Written unconditionally it reached **tetris**, which never opted in: its 488×930 sidebar became a scroll container with `overscroll-behavior: contain`, so a wheel event landing anywhere over it stopped reaching the document and `verify-tetris-topbar-mobile`'s "滾轮下滚能滚起来" went red (scrollTop=0 / max 53) while every other checker stayed green. Gate it on `body.has-frame-budget` (added by `bindFrame()`), the same not-viewport-dependent criterion `game-drawer.js` uses for `has-stats-drawer`. The general rule: before adding anything to `css/layout.css`, check what it does to the pages that did **not** opt in — `node scripts/layout-metrics.mjs` prints all 13 pages for exactly this reason.

- ⚠️ Never put `position: fixed` on `body` of a game page (tetris did, until 2026-09-18). When `html`'s overflow is `visible`, the body's `overflow` is **propagated to the viewport** and the body gets no scroll box of its own; a fixed body then leaves `html` with zero in-flow content, so viewport scrollable height = viewport height and the document **cannot be scrolled at all**. Every path stays at 0 — `scrollTop = N`, `scrollTo()`, `mouse.wheel`, a real touch drag — even though `body.scrollHeight > body.clientHeight` still reports `true`, so it looks scrollable in devtools and to every geometry checker. Symptom: everything below the fold is unreachable (tetris mobile hid Level/Lines/Combo/Next Piece/More Games below SCORE; desktop hid Global Top 5). Keep `body` in flow and use `.game-locked` when you must freeze scrolling during play. Reserve the fixed bottom bar's height on the body: `padding-bottom: calc(<bar height> + env(safe-area-inset-bottom, 0px))`, declared at the **same breakpoint where `.mobile-controls` turns `display: flex`** (≤768px, not only ≤480px) — the bar is 76px (2px top border + 12px padding ×2 + the 50px `.mobile-controls .btn` min-height that the narrow-screen `.btn` rules cannot override), while only 72px was reserved. Regression: `node scripts/verify-tetris-topbar-mobile.mjs` (asserts script/wheel/touch scrolling actually moves, and that the last card clears the bar's top edge). ⚠️ That script must start its touch drag **outside** the board — the canvas has `touch-action: none`, so a drag starting on the board legitimately does nothing

- ⚠️ A hit-area expander `::after { position: absolute; inset: -6px }` resolves against the nearest **positioned** ancestor: if its host is `position: static`, the expander becomes an invisible layer stretched over the whole `.game-container` (found on tetris's `.theme-toggle`, which hit-tested at the board centre and over SCORE). It stays silent because `elementFromPoint` still returns whatever paints later, so clicks land — assert a far point instead of eyeballing: `node scripts/verify-tetris-topbar-mobile.mjs` requires that a point 40px below and 120px left of the pill does **not** resolve to it. `.icon-btn` already carries `position: relative`; any new expander host must set it too

- A playfield (canvas/board) is an **operating surface, not a button** — never give it `:active`/`:hover` transforms or transitions. `#tetris:active { transform: scale(0.99) }` (removed 2026-09-18) made the board shrink-and-spring on every finger touch, and since `#particleCanvas`/`#lineClearCanvas` are absolutely-positioned *siblings* they do not scale with it, so board and effects drifted apart for the length of the transition (measured: 280×560 → 277.2×554.4, overlays off by 1.4px/2.8px). Keep `transition: none` on the canvas as a guard, keep `touch-action: none` on it, and set `touch-action: manipulation` on `html, body` so a fast double-tap on the surrounding area cannot zoom the page (pinch-zoom stays available — don't use `user-scalable=no`). Regression: `node scripts/verify-tetris-touch.mjs` — it must press and hold the board, because the rule only applies while `:active` is live, and a plain "measure the initial layout" check passes on the broken build

## 共享层迁移与剪枝

- Pruning shared-layer duplicates must never drop `color` / `font-family` / `backdrop-filter`: they are the page's own palette, font and material, and `css/layout.css` provides no replacement. Removing them once turned every topbar icon pure black and dropped the pages onto the browser's default serif font. The migration script's `BODY_STRIP` / `ROLE_SPECS` lists now exclude them, and `scripts/fg-audit.mjs` guards the regression

- ⚠️ **A migration script must never replace an existing node with a freshly generated one.** Doing so silently drops its `id`, and the page JS is still calling `getElementById` on it: `sf-btn-sound` / `na-btn-sound` vanished and `js/sword-flight.js:775` / `js/needle-awn.js:928` threw a null deref **inside the constructor**, so both pages failed to boot at all; `wd-btn-help` went with its wrapper and left the help modal with no entry point. `apply-header-footer.py` now refuses to write when any `id` would disappear — keep that guard

- ⚠️ **对象式 `manualChunks` 会把列出模块的整条依赖图打进该分块。** 2026-09-21：`math-rain/main.js` 被放进 `math-rain-core`，它 import 的 `safe-storage` / `site-settings` / `icons` / `analytics` 跟着进去；其它 14 个页面为了拿这些共享导出必须加载整个 `math-rain-core`，顶层 auto-init 在缺 `#game-canvas` 时弹出「❌ 游戏初始化失败」。源码态 `npm run dev` 走模块图，**只有 prod 产物会中招**，对源码跑 smoke 全绿。规约：不要再给带页面副作用的入口写对象式 `manualChunks`；auto-init 必须先确认宿主 DOM（`main.mr-main` + `#game-canvas`）。回归：`node scripts/verify-chunk-isolation.mjs`（配置无 `manualChunks` + 门闩存在 + 若有 dist 则其它 HTML 不得引用 `assets/js/math-rain*`）

- ⚠️ **Never delete a nested HTML block with a lazy `.*?</div>` regex — it stops at the *innermost* closer and leaves orphaned closing tags behind.** Removing sword-flight's sidebar `more-games` card this way matched through `</div>` of `.more-games-links` instead of the card's own, leaving two stray `</div>` that closed `<aside>` and `.game-shell` early. The visible symptom was three steps removed from the cause: `<footer>` ended up a *sibling* of `.game-shell`, so `bindFrame`'s `shell.querySelector(':scope > .game-footer')` returned null, `--frame-chrome` silently dropped 143px → 70px, the stage was computed too large and the page overflowed. A `count('class="more-games"') == before - 1` assertion passed straight through it. Walk the tags and balance the depth instead, assert `block.count('<div') == block.count('</div>')` on what you cut, and verify the *structure* afterwards (ancestor path of a known node vs. the baseline) — not just that the target string is gone. `verify-desktop-frame.mjs` now asserts topbar and footer are **direct children** of `.game-shell`, because `bindFrame` degrades silently otherwise.

- ⚠️ When a codegen script appends to a JS object literal, **adding the missing trailing comma must not `rstrip()` away the line's newline** — that glues the new key onto the previous line and shifts every later offset (it duplicated one key per table across 11 files). Duplicate keys are legal in ES modules, so `node --check` passes and nothing breaks visibly; scan for "same key >2×" instead

- ⚠️ Python's `read_text()`/`write_text()` silently converts CRLF to LF, so any migration script written that way flips the line endings of every file it touches (this bit twice in one session — ~11000 lines of phantom diff). Read bytes, detect the original ending, and restore it on write; before committing, diff endings per file with `git show HEAD:<f> | grep -cU $'\r'`. A `.gitattributes` with `* text=auto eol=lf` would fix it permanently but renormalizes the whole repo on the next `git add -A`, so it needs its own commit

- ⚠️ **A `show()/hide()` helper whose class name exists nowhere is a silent no-op that breaks the game, not the layout.** silk-dew's helpers toggled `is-hidden`; the CSS and every HTML initial state use `hidden` (`.hidden { display: none !important }`). So `hide(start)` never removed the start overlay: it kept painting above the canvas and swallowed **every pointer event**, which surfaced as five unrelated-looking smoke failures — `drags` stuck at 0, the pearl moving 1.4px instead of 400px, `state=playing` instead of `won-level`, and "开始覆盖层未隐藏". This is the same failure shape as the `::before` overlay trap above, and geometry checkers cannot see it. **Always assert the overlay actually lost the class, then drive the real input path** — `scripts/smoke-silk-dew.mjs` moves the real mouse in 30 steps and asserts the HUD counter incremented.

- ⚠️ **When a data provider's return type changes, grep every caller for uses that still assume the old type.** `dailyCourse()` was changed to return level *objects* (so callers needn't re-index `LEVELS`), but `startDaily()` still did `this.startLevel(course[0])` with `startLevel(idx) { this.spec = LEVELS[idx] }` → `LEVELS[object]` is `undefined` → `Cannot read properties of undefined (reading 'par')`, so the whole daily mode threw on entry. The smoke run caught it only because it exercises daily after the campaign path. Make the receiver accept both (`const spec = (ref && typeof ref === 'object') ? ref : LEVELS[clamp(ref, …)]`) and, when the value is used for display too, resolve the index with `LEVELS.indexOf(spec)` rather than assuming it *is* one.

## JS 生命周期与时序

- ⚠️ Never reach a module-level `const` singleton through `typeof`: `typeof x` only protects against **undeclared** identifiers — for a `const`/`let` still in its **temporal dead zone** the `typeof` expression *itself* throws `ReferenceError`. So a helper written as `function current() { return typeof game !== 'undefined' ? game : null; }` cannot protect itself, and it fails exactly when it is needed most: the constructor runs before `const game = new Tetris()` finishes, so anything the constructor calls (`init()` → `updateDisplay()` → `updateHud()` → `renderThemeToggle()`) blows up with `Cannot access 'game' before initialization`. Use a mutable holder assigned right after instantiation and read that:
```js
var gameRef = null;                       // 模块级 var，无 TDZ
function currentGame() { return gameRef; } // 延迟解析，任何时刻调用都安全
const game = new Tetris();
gameRef = game;
window.game = game;                       // 与 sword-flight 一致，便于回归脚本观察
```
Also pass the instance in where you already have it (`updateHud(g = currentGame())`, `renderThemeToggle(this.isRainbowTheme)` from inside the class) so the constructor path never depends on the binding at all

- Also treat a `cancelAnimationFrame` as incomplete until you **null the id**: `animationId` is the single source of truth for "is the loop running", so leaving a stale id behind (tetris's `init()` did, until 2026-09-19) makes every downstream `animationId !== null` guard report a running loop forever — the drawer's "pause the game while open" then silently no-ops on the second start. Set `this.animationId = null` next to both `cancelAnimationFrame` sites

- ⚠️ `getComputedStyle().maxHeight` **resolves `dvh` to px** (`90dvh` on a 844px-tall viewport reads back as `759.6px`), so an assertion like `/dvh/.test(cs.maxHeight)` can never pass — it is a bad test, not a bad value. When the authored *unit* is what matters (e.g. proving the drawer cap tracks the mobile address-bar inset instead of `vh`), assert the **CSS source**: `readFileSync('css/layout.css', 'utf8')` + `/--drawer-max:\s*90dvh/`. Assert computed px only for the derived effect (panel height ≤ cap)

- ⚠️ **A host-mismatched class name makes a whole CSS block silently inert — and the symptom shows up three steps away.** silk-dew's `renderLevelGrid()` emits `class="sd-chip"` while `css/silk-dew.css` defined `.sd-level-chip`. Nothing errored: the container rule (including its `color: var(--tok-text)`) simply never applied, so `.sd-chip-num { color: inherit }` inherited the **black** text colour of the light-surface start overlay it sits inside. On the dark garden background the level numbers were invisible, and `fg-audit` flagged it as `纯黑=20 span.sd-chip-num`. The fix is not "add a color to the child" — it is to make the selector match the emitted class. **Whenever JS generates DOM, grep the CSS for the exact class string the JS writes** (`Grep '"sd-chip"' js/` vs `Grep '\.sd-chip' css/`); a checker that only inspects colours will keep reporting the same 20 hits no matter how many times you patch the child. Corollary: a component that can sit on **both** a light and a dark surface must declare its own colour — never `inherit`.

- ⚠️ **Size a canvas from `clientWidth`, never from `getBoundingClientRect().width`.** silk-dew's `resize()` used the rect (fractional, e.g. 491.33) while `verify-desktop-frame.mjs` compares the backing store against `clientWidth` (integer, 491). Rounding down left `attrW 488 < clientW 491` at every desktop width — the browser then scales a 488px buffer into a 491px box, i.e. a permanently blurry canvas, and the checker calls it `画面糊`. Use `canvas.clientWidth / logicalWidth` (lumen's口径) and remember to also listen for `game-frame:changed`: `--frame-chrome` writing changes the stage width *after* the initial resize, so a `resize`-only listener misses it.

## 桌面舞台预算与画布缩放

- ⚠️ **`ctx.scale()` is cumulative — a resize handler added on top of it doubles the zoom on the second call.** needle-awn's `setupCanvas()` used `ctx.scale(this.dpr, this.dpr)`; the moment it gained a resize listener it would have blown up. Use idempotent `ctx.setTransform(s, 0, 0, s, 0, 0)` in any resize-driven canvas sizing (see gd/na/sf).

- ⚠️ **`--frame-chrome` feedback loop**: chrome → stage width → shell max-width → topbar width → possible topbar wrap → topbar height → chrome again (td's three state pills sit exactly on this path). Guards in `bindFrame`: 1px dead-band, rAF-batched writes, lock + `console.warn` after 10 writes in 500ms; `verify-desktop-frame.mjs` reads `--frame-chrome` twice 500ms apart and asserts equality.

- ⚠️ **Inline `style.width` self-lock** (hs/pm): `resize()` wrote `canvas.style.width`, then read `canvas.clientWidth` as the next input — inline beats `width: 100%`, so the canvas never grew with a wider stage. Measure the parent (`.hs-stage`/`.pm-stage`) instead. Related: hs/pm's `usedH` used to measure `.game-main`'s non-stage children (= the sidebar, not "viewport minus topbar/footer" as the comment claimed); measure `.game-shell` children excluding `.game-main`.

- ⚠️ **`--frame-chrome` is only correct for the `topbar / main / footer` shell shape that `bindFrame` assumes.** gomoku's shell has five in-flow children (topbar · status bar · board · controls · footer), an 18px flex `gap` between each, and 12px of padding on the stage itself — bindFrame counted 166px of a real 334px, so the board was laid out 138px too tall and the desktop page scrolled. Pass the remainder through `extraChrome`, and when summing there, add **heights and `gap` but never margins on the footer**: `.game-footer` carries `margin-top: auto`, whose computed value is the leftover whitespace, so counting it makes the board shrink, which creates more whitespace, which shrinks it again. Heights and gaps are slack-independent and therefore a stable fixed point.

- ⚠️ **Capping a sidebar means deciding what may fall below the scroll line.** Opting tetris into the sidebar cap put **Pause and Restart** outside the visible area at 1280×900 — reference content scrolling is fine, live game controls scrolling is not. The fix was ordering, not geometry: `.info-box.controls` now sits first in the sidebar, ahead of `#statsPanels`, so only the leaderboard scrolls. Check with the sidebar child-position dump before assuming a cap is harmless. Related: `verify-tetris-topbar-mobile.mjs`'s "tail content reachable" assertion now scrolls every `overflow-y: auto|scroll` container inside the shell before measuring — the point is *reachability*, and nested scroll containers are legitimate; it still fails if the document itself cannot scroll.

## 抽屉 / 顶栏行为

- ⚠️ **The `:has()` trap — this is the one that silently fails.** Do **not** gate the sidebar-yield on `.game-sidebar:has([id$="StatsPanels"])`. By CSS-evaluation time the JS has *already moved* that node into the drawer body (which is the whole point of it), so the sidebar contains no such node, `:has()` never matches, and the sidebar just stays `display: block` — while every other assertion passes. The criterion has to come from a fact that does **not** change with the viewport: `js/game-drawer.js`'s `init()` does `document.body.classList.add('has-stats-drawer')` and `layout.css` uses
  ```css
  @media (max-width: 1023.98px) { body.has-stats-drawer .game-sidebar { display: none; } }
  ```
  tetris was migrated onto this same shared rule (its page-owned duplicate in `css/tetris.css` is gone) so all 7 pages run one code path

- ⚠️ **`bindChrome`'s `owns` must not include `sound` on a page that already wires its own mute button** (9 of them do, and they also do page-private work like `SFX.init()` in that handler). Two handlers on one button means a single click toggles twice — **net effect zero** — while every geometry and label assertion stays green. Only genuinely new buttons (gomoku / tetris) pass `'sound'`. `verify-chrome.mjs` asserts "one click must flip `site_muted`" precisely to catch this

- ⚠️ **`owns` must be complete, or the footer "More games" button is simply dead.** silk-dew's `bindChrome({ owns: ['lang'] })` left `more` unclaimed, so nothing was bound to the footer button: `aria-expanded` stayed `false`, the nav stayed `hidden`, and the list stayed empty — three `verify-chrome.mjs` failures with no console error. `bindChrome`'s default is `['lang','more']`; only pass an explicit `owns` when you are *deliberately* excluding a role, and if you do, check each excluded role has a real handler elsewhere.

- ⚠️ **Never wire a click handler on your own `[data-chrome="lang"]` button.** silk-dew's `initUI()` bound one on `sd-btn-lang-ui` *and* `bindChrome` bound one → a single click ran `setLang` twice, so `site_lang` was written back to its original value and every visible label looked unmoved (`语言钮未写入 site_lang` / `语言钮自身文案未变`). This is the language-button twin of the `sound` trap above. Ownership is all-or-nothing per role: either the page renders only (`innerHTML = ICONS.globe`) and chrome owns the click, or the page owns it and chrome must not. **Buttons inside an overlay are the exception** — `#sd-start-lang` carries no `data-chrome`, so the page really must bind it, and dropping that handler leaves a dead button.

- ⚠️ **`applyLanguage()` must rewrite `document.title`, and any HUD it is responsible for must render before a game starts.** Two silent gaps found together on silk-dew: (a) `document.title` was never set, so `verify-chrome.mjs`'s "switch language → the footer hint **and** `document.title` must change" stayed red even though every DOM string localised correctly; (b) `updateHud()` guarded the level line with `else if (this.spec)`, so in the menu state (`spec === null`) the HUD kept the static English `Level 1/20` from the HTML and never localised. Both are the same root cause: localisation code that only runs *after* the game starts. Have `applyLanguage()` write `document.title` and call every renderer unconditionally, and give those renderers a sane pre-game default.

- ⚠️ **`getText` on the shared layer means "return the whole table", not "look up one key".** `bindChrome` and `createStatsDrawer` both declare `@param {() => object} getText` and call it as `getText()` — then read `.home` / `.sound` / `.moreGames` / `.stats` / `.close` off the result. silk-dew was the one page that passed a *per-key* lookup (`(k) => game.t(k)`), so the shared code got `t(undefined)` → `undefined` → `|| {}` → every shared label fell back to its built-in English and stayed there. Seven pages got away with the same mistake being absent; silk-dew's version was invisible in every geometry assertion and only `verify-stats-drawer.mjs`'s `[zh] 文案已本地化` caught it (`stats=Stats close=Close title=Stats` under a 中文 page). The page now exposes `SilkfallGame.textTable()` returning `LANGUAGES[this.lang] || LANGUAGES.en` (which already carries `COMMON_TEXT` on its prototype, so `close` / `moreGames` / `sound` / `language` resolve), and **both** `createStatsDrawer` and `bindChrome` take `getText: () => game.textTable()`. When a shared module's option is a getter, check the call site's *arity*, not just its existence — `(k) => t(k)` looks perfectly reasonable and is silently wrong

- ⚠️ **A shared renderer must not nest its i18n work inside `if (ICONS)`.** `js/game-drawer.js`'s `renderIcons()` originally read
  ```js
  if (ICONS) { /* 图标 */ ; btn.setAttribute('aria-label', statsLabel); /* 文案 */ }
  ```
  i.e. "no icon table handed in" silently also meant "no `stats`/`close` text". Fix it at the *shared* layer — `init()` now calls `this.renderIcons()` unconditionally and the `site-settings:changed` listener only re-renders; do not "fix" it by adding one more call in the affected page. Corollary: when a shared module takes several optional collaborators (`ICONS`, `getText`, `Sfx`), make each *feature* it gates independent of the others — one `if (optionalThing) { …all the rest… }` is a latent per-page bug, not a convenience

- ⚠️ **Label/aria text needs its own per-language assertion.** Geometry and clickability checks stay green while a button silently falls back to English — that is exactly how a missing `close` key slipped through (the i18n migrator unpacked `(ck, cv)` in its `for` loop and then never used it, so only `stats` was ever written). `verify-stats-drawer.mjs` now asserts `aria-label` on the Stats button, `aria-label` on the close button and the drawer title for **both** `zh` and `en`. Two gotchas: the language is stored under **`site_lang`** (`LANG_KEY` in `js/site-settings.js`) — seeding `'lang'` leaves the page on its `navigator.language` default and makes every "Chinese didn't apply" failure a *phantom*; and the tables are named **`LANGUAGES`** on pm/hs/td/gd (`this.TEXT` is only a class-property alias) but `I18N` on na/sf

## 结算与渲染单一出口

- Render the game-over state from **one** place, not inline in the end handler. Two traps found in gomoku on 2026-09-18: (1) `endGame()` returned straight after `showModal()`, so the status bar still read "Black's Turn" while the overlay read "Black Wins!"; (2) `applyLanguage()` re-localised the overlay title and buttons but **not** the result message, so switching language left "Black Wins!" under a 中文 title. Pattern: keep the result in state (`lastResult`) + one `resultText(t)` renderer shared by `endGame` and `applyLanguage`, and let `updateStatus()` branch on the ended state. Note the path is reachable even though the overlay covers the top bar — Tab + Enter dispatches the element's own `click`, bypassing hit-testing — while `page.click()` on such a covered control just closes the overlay, so assert with `page.$eval('#id', el => el.click())` (see `scripts/verify-gomoku.mjs`)

## 按钮与图标

- Emoji as a *button label* also breaks vertical centring, not just policy: `🌈 Theme` at 10px measured 4px above the pill's centre (7px gap above vs 15px below), because the emoji's font metrics inflate the line box while `display: block` + `line-height: normal` places the Latin text on the shared baseline. Use inline SVG + a flex host + `line-height: 1` so centring comes from layout, not glyph metrics; keep label + `aria-pressed` in **one** renderer (`renderThemeToggle()` in `js/tetris.js` — three code paths used to write this label, and a rewrite without the icon silently drops it). The theme toggle is a real `<button>` now, so it is keyboard-focusable. Known remaining gap (not yet fixed): on **short** viewports the board's bottom sits under the fixed bar — 320×568 hides 124px, 360×640 hides 52px, 375×667 hides 25px (≥740px tall is clean) — fixing it needs the board's `max-height` to follow viewport height

## 校验基础设施

- ⚠️ **`scripts/serve-static.mjs` 不回退 `public/`，于是 `public/` 下的一切在校验里都是 404 —— 而且没有任何检查会因此变红。**
  Vite dev 与 `dist/` 都把 `public/` 挂在站点根，但这台校验服务器只认仓库根：`/sw-register.js`、`/analytics.js`、

## codegen 脚本

- ⚠️ **Never mutate a string while iterating its own match offsets.** The dedupe pass in `add-drawer-i18n.py` sliced `block` inside a loop over `finditer(block)` — the offsets are relative to the *original* string, so once the first removal shifts them, every later cut lands on arbitrary characters (it split `'开始新的每日挑战？…'` mid-string), and reassembling with `tail[len(block):]` reused an already-shortened length. All six JS files became syntax errors and had to be hand-repaired, because the damage spanned entire i18n tables and `git checkout` would have discarded the session's real work. Safe form: collect every hit's **absolute** `(start, end)`, delete **backwards on the whole `src`**, return once. Pair it with: `--dry` support, a `cp`'d scratch copy + `node --check` before touching real files, and **`md5sum` twice** to prove idempotence — never trust the script's own printed "skipped" report, since `tail -N` truncates lines and misleads. Related: a dedupe window that starts at `pos` can never see the key it is looking for, because `pos` points at that key's own indentation and the slice has no leading `\n` for `r'\n[ \t]*key:'` to match — start the preview at `pos - 1`

- ⚠️ **迁移器会静默空转，而空转和成功长得一模一样。** 2026-09-20 排查发现两处叠在一起：
  (1) `add-drawer-i18n.py` / `add-chrome-i18n.py` 的表定位正则还是 `const LANGUAGES = {`，
  而 P2 的 i18n 收敛早把源码改成了 `const LANGUAGES = makeText({` —— 12 个页面全部匹配不上，
  脚本逐页打印「!! 找不到表」然后**以 0 退出**，看上去和「无事可做」没区别；
  (2) 页面清单是手写数组，新游戏不补进去就根本不在循环里，连一行输出都不会有。
  两者合起来：lumen 上线后跑 CLAUDE.md 写的那套迁移命令，屏幕上一片祥和，实际什么都没发生。
  规约：迁移器的页面清单一律 `REGISTRY.with_cap(...)` 派生；表名走 `i18nVar`；
  `!!` 必须换成非零退出（`return 1 if bad else 0`）；跨版本的结构假设（表被 `makeText(...)` 包过）
  写进正则时要同时认新旧两种形态。反向验证：摘掉一条注册表条目跑脚本，必须红。
- ⚠️ **修活一个迁移器之前，先确认它要写的东西现在还该不该写。** 上面那两个脚本一旦恢复匹配，
  就会按 P2 之前的清单往每页插 `sound` / `moreGames` / `close` —— 而这三个键那时已被收进
  `js/i18n.js` 的 `COMMON_TEXT`，靠 `makeText` 原型链兜底，页面里留副本会被
  `verify-i18n.mjs` 的「无公共键字面量副本」判红。也就是说「修好」的脚本会当场把 12 个页面改红。
  判据同样不能再抄一份：`scripts/lib/i18n_common.py` 现读 `COMMON_TEXT` 的键集合并剔除。
- ⚠️ **收紧一条断言时，先确认宽松版不是在容忍某种合法形态。** 给 `add-chrome-i18n.py` 加
  「缺 hint 文案要报错」之后，minesweeper 立刻两条 `!!` —— 它的页脚提示本就是按插旗模式切换的
  `hintDefault` / `hintFlagMode` 两条，不是单个 `hint`。正确做法是按事实放宽成 `hint\w*` 家族，
  而不是给 minesweeper 加一条豁免：豁免会把「这页有合法的另一种形态」记成「这页有问题」。
