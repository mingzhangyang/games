# 四色图志与七桥漫游 共同方向与交付方案

> 状态：完整实现方案，尚未实现或发布。
> 日期：2026-10-12 · 设计版本：1.1 · 名称为工作名。

两款游戏分别建立独立的美术与交互语言，以可推理、可探索、可收藏的体验扩展 games 的图论题材。

- [四色图志完整实现方案](proposal-fourfold-atlas-design.md)
- [七桥漫游完整实现方案](proposal-seven-bridges-design.md)

本方案定义正式首发目标。先用纵向切片验证关键乐趣，再制作完整章节。关卡数量、性能预算与用户测试门槛均为设计目标；样例验证状态见文末。

## 共同方向与关键决策

现有项目具备 25 款内置游戏，并通过 `site.home.externalGames` 接入 2D 我的世界、点格棋和挑棒。本次确定采用同一外链组织方式：四色图志与七桥漫游各自独立仓库、独立部署，games 仅承担发现与导航。新作参考现有可靠性实践，自主维护实现，不受合集页面壳、CSS 或交互样式约束。

### 四色图志 Fourfold Atlas

玩家是一位修复失色地图的制图师。铺色、调整相邻关系、交换一片双色区域，让地图册逐页恢复生机。

**主动作：**点选颜色并填色。<br>**标志动作：**预览并交换完整双色连通片。<br>**情绪：**专注、舒展、完成作品的满足。

概念配色：`#c9654f` / `#ddb858` / `#4c8b86` / `#6a6eab`。

### 七桥漫游 Seven Bridges

玩家在一座微缩河港中散步、遇见死路、理解桥梁结构，再通过改建让原本不可能的旅程成为现实。

**主动作：**逐桥行走。<br>**标志动作：**城市与点线图连续变形，以及修桥后亲自走通。<br>**情绪：**探索、顿悟、改变世界的成就感。

概念配色：`#1c3846` / `#558b97` / `#d0a56a` / `#eab86d`。

| 决策 | 执行方式 |
| --- | --- |
| 精彩来自主机制 | 四色围绕空间约束和成组换色；七桥围绕路线与结构改建。首发不加入体力、抽卡、货币、战斗或广告奖励。 |
| 数学通过操作出现 | 先让玩家观察现象，再用短动画解释。术语与历史放入可选图鉴，不在开局铺满说明。 |
| 探索无需惩罚 | 故事关不限时、无限撤销；失败保留现场。通关凭规则，不依赖动画播放完成。 |
| 作品有余韵 | 完成后的地图成为收藏页；走通的城市保留路线明信片。结算不立即遮住舞台。 |
| 重玩有真实变化 | 每日关卡需改变图结构、固定线索或建设选择；仅旋转场景、换色或换皮不计作新谜题。 |
| 首发无全球排行榜 | 采用完成印章、额外挑战和每日分享。先避免提示、撤销、重试与跨设备计分的不公平；后续如加榜，单独定义可验证挑战模式。 |

## 独立项目与完整交付路线

### 1 仓库边界与合集接入

项目参考基线为 games 的 `main@d317af4`。此 SHA 只说明调研背景，不作为新项目代码起点；两款在各自仓库初始化，不从 games 分支复制整个应用。本 PR 只修改设计，不创建仓库、配置域名、发布站点或改动注册表。

| 仓库 | 所有权与职责 | 建议部署地址 |
| --- | --- | --- |
| `games` | 首页卡片、游戏介绍、固定外链、总体规划和文档索引 | 现有 `games.orangely.xyz` |
| `four-colors` | 四色代码、关卡、素材、设置、存档、测试与详细设计 | `four-colors.orangely.xyz` |
| `bridges` | 七桥代码、关卡、素材、设置、存档、测试与详细设计 | `bridges.orangely.xyz` |

两个仓库已经创建；子域名仍为规划值，尚未配置。每款拥有独立构建与发布配置，目标为各自的 Cloudflare 静态站点部署；不通过 games 的部署产物承载游戏，也不在运行时依赖 games 的资源可用性。

**合集侧边界：**上线后仅在 `site.home.externalGames` 添加稳定 ID、正式 URL、中英文名称、介绍、标签及配套卡片图标，运行 `npm run gen` 更新派生内容。不要加入内置 `games` 数组，不登记内置 entry/caps，不运行 `new:game` 生成器，也不为它们扩展合集的布局/CSS/性能场景契约。现有生成器缺少所需卡片能力时，只做可复用的目录功能调整。当前 externalGames 只生成静态 URL，不假设它已经会传递用户设置。

两款使用自己的导航、工具栏、主题和可见视口布局；保留键盘、屏幕阅读器、安全区、触控下限与减少动态的质量要求，不搬用 shared chrome 或 immersive 壳。每款提供固定“返回游戏合集”链接，目标为 `https://games.orangely.xyz/`，不接受任意外部 returnUrl。

### 1.1 基础能力与跨域设置

| 能力 | 独立项目方案 | 边界 |
| --- | --- | --- |
| 存档 | 本地版本化 adapter、单快照、明确写入结果和迁移测试 | 各自 origin 独立，不能读取 games 的 localStorage 或 IndexedDB |
| 设置 | 各自 settings 服务；保存语言、主题和静音 | 不依赖 site-settings 事件，不承诺跨站同步 |
| 每日日期 | 各自实现并测试 UTC+8 日期与固定内容版本 | 可以参考现有 daily 工具，不远程导入；无需保持与已有游戏相同的随机序列 |
| 构建与 CI | 两个独立 Vite 项目、锁文件、测试命令与发布配置 | 单款提交不触发 games 或另一款的全量测试与发布 |
| 复用 | 参考成熟行为，必要时有来源记录地移植小型工具并本地维护 | 不整体复制 src/platform，不建立跨站脚本依赖或提前发布通用 SDK |

首访设置协议可选，游戏直达访问必须完整可用：仅接收白名单参数 `lang=en|zh` 和 `theme=light|dark|system`，各字段优先级为“有效已存偏好 > 有效入口参数 > 浏览器语言/系统主题”。非法参数忽略；解析后只删除已识别的设置参数，保留关卡、日期等其他参数。静音不通过 URL 传递，默认静音，声音启用需用户手势。

若 games 需要传递当前设置，应在后续外链接入 PR 显式实现并测试，不能把参数硬编码成所有人的默认值。复制链接、直接打开和浏览器返回均不覆盖游戏内已有设置。首发不建设跨域账号、存档同步、共享 Cookie 或 iframe 通信。

主题外观由各游戏决定：四色的夜间呈现为夜灯下的纸页；七桥的浅色模式为日景河港。逻辑颜色和图案在切换主题时保持身份。

### 1.2 文档单一归属

详细设计已经分别加入 `mingzhangyang/four-colors` 与 `mingzhangyang/bridges` 的文档 PR（各自的 `docs/implementation-plan.md`）；合并后，这两份独立仓库文档成为各自游戏的持续维护副本。games 中保留总体交付方案、外链边界和交接链接；若后续修改详细规则，应优先在对应独立仓库更新，再回写 games 的摘要。不要在三个仓库持续编辑同一份详细规格。

### 2 技术选型与资产预算

每款采用 vanilla JavaScript＋Vite 单游戏入口，独立维护 package.json、锁文件和资源目录。游戏场景首选 SVG＋HTML 控件，完成明信片时可导出为 Canvas 图像；不加入 React、WebGL 或物理引擎。相机、移动与动效只更新 transform、opacity 或有限 SVG 属性，尽量避免持续大面积滤镜。

两款不共享规则层：四色的对象是区域邻接约束，七桥的对象是带重边的遍历图。初期不提取泛用 graph library。只有两个实际实现均出现稳定重复、且语义相同的工具时，才讨论共享。求解与内容验证分别可在 Node 中运行，不依赖 DOM。

| 目标预算 | 建议值 | 验证方式 |
| --- | --- | --- |
| 首屏新增游戏 JS | 每款 gzip ≤150KB，题库和后续章懒加载 | 独立生产构建统计，包含本游戏全部首屏运行时代码 |
| 首次可玩必需美术 | 每款压缩后 ≤1MB | 按实际请求图统计，不把预加载隐藏在后台预算外 |
| 全部章素材 | 每款约 4—8MB 上限目标 | 按章加载；移动端首开不加载全部图片 |
| 普通输入 | 逻辑同步工作 <8ms，反馈应在下一可用帧呈现 | 记录设备与浏览器；不能拿容器浏览器成绩充当真机成绩 |
| 待机 | 无持续游戏绘制循环 | 观察 rAF、定时器、任务与后台恢复；声景可关 |

这些是实现目标，不是已完成的性能承诺。若精确描边和艺术效果冲突，保留可读边界；若图景变形成本过高，先采用对应元素交叉淡变，仍保留同一状态映射与设计辨识度。

### 3 实施批次与退出条件

| 批次 | 内容 | 可以进入下一阶段的证据 |
| --- | --- | --- |
| D0 独立项目与样机 | 初始化两个仓库和各自 CI；迁入详细设计；四色 4 个关键图、七桥 3 个精确图，纯模型、撤销与触控；不登记首页 | 本方案样例机器验证通过；两款各自核心动作可玩；没有只展示动画的假原型 |
| A1 四色纵向切片 | 第一章 8 关＋2 个交换实验关；接存档、真实颜料反馈、窄屏布局和无障碍 | 首关易懂；改色能产生思考；交换工具至少在两个实验关提供价值 |
| A2 四色内容完成 | 32 主线、8 短篇、4 章美术、提示、收藏、导出与每日清单 | 关卡证书与审核齐全；全流程可用；所有目标素材有合法来源 |
| A3 四色发布与接入 | 四色仓库独立部署、域名/SEO、完整回归与真机验收；随后单独提交 games 外链 PR | 正式 URL 与关卡深链可用，卡片及返回导航通过后展示入口 |
| B1 七桥纵向切片 | 6 个路线关＋原版七桥发现样机＋1 个工程关；城市与图切换 | 平行桥可点、拖动可靠；玩家看得懂切图；修桥后愿意亲自走一遍 |
| B2 七桥内容完成 | 32 主线、8 委托、完整发现演出、每日清单与明信片 | 历史无解不误导，工程最优值有证明，所有桥位触控审核通过 |
| B3 七桥发布与接入 | 七桥仓库独立部署、完整回归与真机验收；随后单独提交 games 外链 PR | 七桥正式站点可用，games 外链接入验证通过，单款更新不联动发布其他游戏 |

推荐顺序为 D0→A1→A2→A3→B1→B2→B3。D0 同时验证两个概念，随后集中完成四色，减少在两个半成品间切换。批次是交付边界，不绑定未经核对的 PR 编号；每个批次可按代码规模拆 PR，游戏开发 PR 留在各自仓库，合集接入使用单独 PR；不为新作改造 games 共享壳。

首次工期应在 D0 后重新估算。作为排期假设，具备素材支持的一位熟悉仓库的开发者，两款合计约 30—45 个有效工作日，包含关卡编排和两轮试玩修订；不含等待外部美术或评审的时间。这不是交付承诺，最大变量是精选关卡与美术迭代，而不是欧拉算法或基础填色代码。

### 4 必测矩阵与发布操作

- 模型：合法与非法拓扑、约束、完整命令回放、撤销重做、可行性与最优性证书；测试不复用待测算法来充当唯一判据。
- 生命周期：加载、恢复、重开、跳关、后台、旋转、帮助、语言切换、主题切换、输入被取消、动画中离开、异步提示迟到。
- 持久化：写入失败、损坏数据、版本变化、历史过长、多标签冲突、每日跨午夜；不把内存成功显示为持久化成功。
- 移动端：390×664、375×553、320×454；横屏 839×360；安全区、动态地址栏、触控下限、浏览器缩放。至少一台真实 iPhone Safari 与一台 Android Chrome。
- 无障碍：完整键盘路径、屏幕阅读器状态、纹理辅助、减少动态、静音、文字对比度；工具栏全称在辅助技术下可读。
- 独立游戏构建：各仓库在 D0 定义 lint、模型/内容测试、浏览器 smoke 与 build 命令；在本仓库 CI 验证，发布前覆盖本游戏全流程。不要调用 games 的 verify-all 或把另一款作为测试依赖。
- games 外链接入：只在添加卡片/注册元数据时执行 `npm run gen`、生成结果检查与现行必要 CI 门槛；验证首页双语文案、图标、正式外链、键盘访问及返回入口。现有注册表变更若要求全量校验，应遵守该门槛；后续独立游戏更新无需再次触发它。

发布顺序为：独立游戏 CI 通过 → 本游戏预览环境验收 → 配置并验证正式域名、资源和深链 → 在 games 添加外链。两款分别发布、分别回滚；预览域名不写入合集正式卡片。games 的自动发布只更新目录，不负责发布两款游戏。

首发不依赖合集计分或统计 Worker，不新增 D1 迁移。以后若接入共享服务，需另行定义 API、跨域策略、数据归属和版本兼容；共享计分 Worker 仍按用户手动发布流程处理，不能把其上线与独立游戏自动部署混为一谈。独立站自身 canonical、sitemap、OG、资源缓存与深链由本仓库负责，games 只维护自己的目录元数据。

性能证据在各自仓库采集，覆盖初次打开、连续操作、动画窗口、闲置和后台恢复；可以参考现有 profile 工具的指标定义，采用少量本地脚本，不为此把外部游戏加入 games 的内置场景清单。不能为了测帧率给待机游戏制造常驻循环。

### 5 风险与有边界的降级

| 风险 | 处理 | 不接受的妥协 |
| --- | --- | --- |
| 四色变成无脑涂色 | 提高线索关系质量，替换弱关，加入成组重排的局面 | 靠更多小碎块、倒计时或付费提示制造困难 |
| 交换工具太复杂 | 延后教学；减少工具步骤；只在精选短篇强制使用 | 移除预览、静默改动锁定区域 |
| 七桥知道定理就无聊 | 加强回路组合、固定起终点、建设选择与连通性陷阱 | 临时塞入钥匙、敌人和随机断桥掩盖关卡单薄 |
| 图景切换不易实现 | 先保证同 ID 对应与清晰淡变，再升级连续变形 | 两套视图产生不同路线或重复桥状态 |
| 每日生产跟不上 | 冻结已审核 60 天清单，按明确节奏补题；到期给精选入口 | 把反复换皮冒充全新谜题 |
| 基础工具在两个仓库重复维护 | 控制本地 adapter 规模，记录移植来源，各仓库独立验证与升级 | 引入全平台复制品、远程运行时或提前搭建 SDK |
| 全量美术拖慢首发 | 复用精致基础材质和少量地标，优先保证每章主视觉 | 在精确谜题中用不可控图片代替边界与桥模型 |

**首发明确不含：**玩家公开编辑器、联网对战、全球排行榜、程序化无限内容、真实地理地图、多人协作、广告奖励系统。它们均不影响这两款游戏的完整性；追加前应先验证新内容是否扩展核心乐趣。

## 依据与交接材料

项目依据为本次直接阅读的注册表及 externalGames 生成流程、架构、GameStorage、daily 工具、电路谜题和每日猜词实现。现有平台模块仅作为实现经验参考，现有布局/样式契约不约束独立游戏。美术、关卡规模、模式与工程切分为本方案的产品设计选择；数学事实与设计建议分别列出。

1. [games.config.json](https://github.com/mingzhangyang/games/blob/d317af4/games.config.json)；[Architecture v2](https://github.com/mingzhangyang/games/blob/d317af4/docs/architecture-v2.md)；[布局契约](https://github.com/mingzhangyang/games/blob/d317af4/docs/contracts/layout.md)。合集接入时以最新 main 的 externalGames 生成流程为准；独立游戏不采用内置 new-game 流程。
2. [Robertson、Sanders、Seymour、Thomas 的四色定理说明](https://thomas.math.gatech.edu/FC/fourcolor.html)：平面地图着色、边界相邻定义和证明背景。不能由此推出任意固定颜色线索可扩展。
3. [Feghali、Johnson、Paulusma，Kempe Equivalence of Colourings of Cubic Graphs](https://arxiv.org/abs/1503.03430)：双色连通分量与颜色交换定义。本方案只使用这一操作定义，不把论文特定图类的结论推广为本游戏任意状态都可互达。
4. [The Bridges of Königsburg 教学资料](https://fanchung.ucsd.edu/152/class/konig.htm)：原版七桥的度数、连通性和欧拉路径判据，以及进入/离开配对解释。
5. [MDN Same-origin policy](https://developer.mozilla.org/en-US/docs/Web/Security/Defenses/Same-origin_policy)：不同 origin 的浏览器存储隔离，包括不同子域名。

**本轮已核对的数学样例：**已用独立穷举检查 K4 的三色不可行与四色可行、C4 两色着色、六区外环对中心的阻塞及重排；已逐桥 ID 回放“两座广场”、七桥加一桥与加两桥的示例路线，并检查原图和改建图度数。其余关卡是待制作的内容规格，不是已生成或已验证的关卡包。
