# 四色图志与七桥漫游 共同方向与交付方案

> 状态：完整实现方案，尚未实现或发布。
> 日期：2026-10-12 · 设计版本：1.0 · 名称为工作名。

两款游戏分别建立独立的美术与交互语言，以可推理、可探索、可收藏的体验扩展 games 的图论题材。

- [四色图志完整实现方案](proposal-fourfold-atlas-design.md)
- [七桥漫游完整实现方案](proposal-seven-bridges-design.md)

本方案定义正式首发目标。先用纵向切片验证关键乐趣，再制作完整章节。关卡数量、性能预算与用户测试门槛均为设计目标；样例验证状态见文末。

## 共同方向与关键决策

现有项目具备 25 款游戏、独立游戏模块、版本化存档、统一语言和音效设置、每日种子与注册生成链。新作复用这些可靠性能力，但不复制既有“深色卡片＋分数框＋侧栏”的外观。视觉自由与架构清晰可以同时成立。

### 四色图志 Fourfold Atlas

玩家是一位修复失色地图的制图师。铺色、调整相邻关系、交换一片双色区域，让地图册逐页恢复生机。

**主动作：**点选颜色并填色。<br>**标志动作：**预览并交换完整双色连通片。<br>**情绪：**专注、舒展、完成作品的满足。

概念配色：`#c9654f` / `#ddb858` / `#4c8b86` / `#6a6eab`。

### 七桥漫游 Seven Bridges

玩家在一座微缩河港中散步、遇见死路、理解桥梁结构，再通过改建让原本不可能的旅程成为现实。

**主动作：**逐桥行走。<br>**标志动作：**城市与点线图连续变形，以及修桥后亲自走通。<br>**情绪：**探索、顿悟、改变世界的成就感。

概念配色：`#1c3846` / `#558b97` / `#d0a56a` / `#eab86d`。

| 决策 | 执行方式 |
| --- | --- |
| 精彩来自主机制 | 四色围绕空间约束和成组换色；七桥围绕路线与结构改建。首发不加入体力、抽卡、货币、战斗或广告奖励。 |
| 数学通过操作出现 | 先让玩家观察现象，再用短动画解释。术语与历史放入可选图鉴，不在开局铺满说明。 |
| 探索无需惩罚 | 故事关不限时、无限撤销；失败保留现场。通关凭规则，不依赖动画播放完成。 |
| 作品有余韵 | 完成后的地图成为收藏页；走通的城市保留路线明信片。结算不立即遮住舞台。 |
| 重玩有真实变化 | 每日关卡需改变图结构、固定线索或建设选择；仅旋转场景、换色或换皮不计作新谜题。 |
| 首发无全球排行榜 | 采用完成印章、额外挑战和每日分享。先避免提示、撤销、重试与跨设备计分的不公平；后续如加榜，单独定义可验证挑战模式。 |

## 平台集成与完整交付路线

### 1 复用底层能力 允许视觉独立

基线为本次阅读的 main 提交 `d317af4`，包含 PR #136。实施前需重新同步 main，核对后续 PR 的生命周期与性能调整，不能直接在旧基线叠加代码。本轮仅设计，不更改线上游戏、Worker 或注册表。

| 保留复用 | 新作自主决定 | 不做的抽象 |
| --- | --- | --- |
| games.config.json 与 npm run gen | 首页封面、主题名、独立页面入口 | 不维护第二份游戏清单 |
| GameStorage、site-settings、daily 日期工具 | 各自模型、存档字段、收藏与进度 | 不新建全站存档或设置系统 |
| 可见视口、安全区、键盘与减少动态基础约定 | 沉浸式画面、底部颜料盒、镜片与工程工具 | 不复制旧 HUD 与统计侧栏 |
| 现有测试发现、构建和发布流程 | 独立模型、关卡与浏览器验收 | 不引入通用图论引擎或大型 3D 引擎 |

两款优先采用现有 immersive 布局入口，但不假设当前壳可以未经调整承载全部新布局。先做三种窄屏布局验证：能用变量表达的扩展放入组件皮肤；确有新的语义组件就命名并明确所有者。若现行契约阻止合理设计，应连同文档和校验器一起更新，不能靠未分层 CSS、特异性竞赛或静默豁免绕过。

主题策略：尊重全站明暗偏好，但“地图册”与“水城”保留各自材质。四色的夜间呈现为夜灯下的纸页；七桥的浅色模式为日景河港。四种逻辑颜色与图案在切换主题时保持身份。所有首发支持能力如实登记，未实现全局榜就不声明 leaderboard。

### 2 技术选型与资产预算

沿用 vanilla JavaScript＋Vite 多入口。游戏场景首选 SVG＋HTML 控件，完成明信片时可导出为 Canvas 图像；不加入 React、WebGL 或物理引擎。相机、移动与动效只更新 transform、opacity 或有限 SVG 属性，尽量避免持续大面积滤镜。

两款不共享规则层：四色的对象是区域邻接约束，七桥的对象是带重边的遍历图。初期不提取泛用 graph library。只有两个实际实现均出现稳定重复、且语义相同的工具时，才讨论共享。求解与内容验证分别可在 Node 中运行，不依赖 DOM。

| 目标预算 | 建议值 | 验证方式 |
| --- | --- | --- |
| 首屏新增游戏 JS | 每款 gzip ≤150KB，题库和后续章懒加载 | 生产构建产物统计，单独报告共享平台开销 |
| 首次可玩必需美术 | 每款压缩后 ≤1MB | 按实际请求图统计，不把预加载隐藏在后台预算外 |
| 全部章素材 | 每款约 4—8MB 上限目标 | 按章加载；移动端首开不加载全部图片 |
| 普通输入 | 逻辑同步工作 <8ms，反馈应在下一可用帧呈现 | 记录设备与浏览器；不能拿容器浏览器成绩充当真机成绩 |
| 待机 | 无持续游戏绘制循环 | 观察 rAF、定时器、任务与后台恢复；声景可关 |

这些是实现目标，不是已完成的性能承诺。若精确描边和艺术效果冲突，保留可读边界；若图景变形成本过高，先采用对应元素交叉淡变，仍保留同一状态映射与设计辨识度。

### 3 实施批次与退出条件

| 批次 | 内容 | 可以进入下一阶段的证据 |
| --- | --- | --- |
| D0 规则与交互样机 | 四色 4 个关键图、七桥 3 个精确图；纯模型、撤销、两种触控输入；不登记首页 | 本方案样例机器验证通过；两款各自核心动作可玩；没有只展示动画的假原型 |
| A1 四色纵向切片 | 第一章 8 关＋2 个交换实验关；接存档、真实颜料反馈、窄屏布局和无障碍 | 首关易懂；改色能产生思考；交换工具至少在两个实验关提供价值 |
| A2 四色内容完成 | 32 主线、8 短篇、4 章美术、提示、收藏、导出与每日清单 | 关卡证书与审核齐全；全流程可用；所有目标素材有合法来源 |
| A3 四色集成发布 | 登记生成、封面、SEO、全量回归、真实手机验收 | CI 与验收通过，才在首页展示完整游戏 |
| B1 七桥纵向切片 | 6 个路线关＋原版七桥发现样机＋1 个工程关；城市与图切换 | 平行桥可点、拖动可靠；玩家看得懂切图；修桥后愿意亲自走一遍 |
| B2 七桥内容完成 | 32 主线、8 委托、完整发现演出、每日清单与明信片 | 历史无解不误导，工程最优值有证明，所有桥位触控审核通过 |
| B3 七桥集成发布 | 登记生成、全量回归、真机与性能验收 | 新增游戏不破坏已有 25 款；平台基础体验保持稳定 |

推荐顺序为 D0→A1→A2→A3→B1→B2→B3。D0 同时验证两个概念，随后集中完成四色，减少在两个半成品间切换。批次是交付边界，不绑定未经核对的 PR 编号；每个批次可按代码规模拆 PR，避免一条 PR 同时承载共享壳改造与所有内容。

首次工期应在 D0 后重新估算。作为排期假设，具备素材支持的一位熟悉仓库的开发者，两款合计约 30—45 个有效工作日，包含关卡编排和两轮试玩修订；不含等待外部美术或评审的时间。这不是交付承诺，最大变量是精选关卡与美术迭代，而不是欧拉算法或基础填色代码。

### 4 必测矩阵与发布操作

- 模型：合法与非法拓扑、约束、完整命令回放、撤销重做、可行性与最优性证书；测试不复用待测算法来充当唯一判据。
- 生命周期：加载、恢复、重开、跳关、后台、旋转、帮助、语言切换、主题切换、输入被取消、动画中离开、异步提示迟到。
- 持久化：写入失败、损坏数据、版本变化、历史过长、多标签冲突、每日跨午夜；不把内存成功显示为持久化成功。
- 移动端：390×664、375×553、320×454；横屏 839×360；安全区、动态地址栏、触控下限、浏览器缩放。至少一台真实 iPhone Safari 与一台 Android Chrome。
- 无障碍：完整键盘路径、屏幕阅读器状态、纹理辅助、减少动态、静音、文字对比度；工具栏全称在辅助技术下可读。
- 生产构建：按当前仓库脚本执行 gen 检查、build 和 verify；注册表变化会扩大测试范围，最终合并前跑全量，不只跑新游戏 smoke。

不因首发无全球榜而修改计分 Worker，不触发 D1 迁移。Web app 仍按现有 Cloudflare 自动发布路径发布。若未来独立加入榜单，须按用户手动发布计分 Worker 的流程安排上线，不能假设前端合并就已支持新分数类型。

本方案不预先重建性能工具；在正式实现时给现有 profile 工具补充两个事件驱动游戏场景，分别测初次打开、连续操作、动画窗口、闲置和后台恢复。不能为了测帧率给待机游戏制造常驻循环。

### 5 风险与有边界的降级

| 风险 | 处理 | 不接受的妥协 |
| --- | --- | --- |
| 四色变成无脑涂色 | 提高线索关系质量，替换弱关，加入成组重排的局面 | 靠更多小碎块、倒计时或付费提示制造困难 |
| 交换工具太复杂 | 延后教学；减少工具步骤；只在精选短篇强制使用 | 移除预览、静默改动锁定区域 |
| 七桥知道定理就无聊 | 加强回路组合、固定起终点、建设选择与连通性陷阱 | 临时塞入钥匙、敌人和随机断桥掩盖关卡单薄 |
| 图景切换不易实现 | 先保证同 ID 对应与清晰淡变，再升级连续变形 | 两套视图产生不同路线或重复桥状态 |
| 每日生产跟不上 | 冻结已审核 60 天清单，按明确节奏补题；到期给精选入口 | 把反复换皮冒充全新谜题 |
| 全量美术拖慢首发 | 复用精致基础材质和少量地标，优先保证每章主视觉 | 在精确谜题中用不可控图片代替边界与桥模型 |

**首发明确不含：**玩家公开编辑器、联网对战、全球排行榜、程序化无限内容、真实地理地图、多人协作、广告奖励系统。它们均不影响这两款游戏的完整性；追加前应先验证新内容是否扩展核心乐趣。

## 依据与交接材料

项目依据为本次直接阅读的注册表、架构、布局/样式契约、GameStorage、daily 工具、电路谜题和每日猜词实现。美术、关卡规模、模式与工程切分为本方案的产品设计选择；数学事实与设计建议分别列出。

1. [games.config.json](https://github.com/mingzhangyang/games/blob/d317af4/games.config.json)；[Architecture v2](https://github.com/mingzhangyang/games/blob/d317af4/docs/architecture-v2.md)；[布局契约](https://github.com/mingzhangyang/games/blob/d317af4/docs/contracts/layout.md)。实施时以最新 main 为准。
2. [Robertson、Sanders、Seymour、Thomas 的四色定理说明](https://thomas.math.gatech.edu/FC/fourcolor.html)：平面地图着色、边界相邻定义和证明背景。不能由此推出任意固定颜色线索可扩展。
3. [Feghali、Johnson、Paulusma，Kempe Equivalence of Colourings of Cubic Graphs](https://arxiv.org/abs/1503.03430)：双色连通分量与颜色交换定义。本方案只使用这一操作定义，不把论文特定图类的结论推广为本游戏任意状态都可互达。
4. [The Bridges of Königsburg 教学资料](https://fanchung.ucsd.edu/152/class/konig.htm)：原版七桥的度数、连通性和欧拉路径判据，以及进入/离开配对解释。

**本轮已核对的数学样例：**已用独立穷举检查 K4 的三色不可行与四色可行、C4 两色着色、六区外环对中心的阻塞及重排；已逐桥 ID 回放“两座广场”、七桥加一桥与加两桥的示例路线，并检查原图和改建图度数。其余关卡是待制作的内容规格，不是已生成或已验证的关卡包。

**实现启动时的第一份交付：**把精确样例写入纯模型并生成验证结果，同时做两款各一个可直接操作的舞台。先确认“看得懂、操作顺、想继续”，再扩展完整内容；正式首发必须同时交付规则、关卡、素材、恢复能力与验收证据。
