## Project Overview

This is a collection of single-page HTML5 games built with vanilla JavaScript, built with Vite and deployed to Cloudflare Workers (static assets via `wrangler.jsonc`). The games include:

- **Math Rain** (`math-rain.html`) - Mathematical expression game with modular architecture
- **Tetris** (`tetris.html`) - Modern Tetris implementation with themes, combo system, and global high scores
- **Tank Battle** (`tank-battle.html`) - Classic arcade-style tank combat game
- **Gomoku** (`gomoku.html`) - Five-in-a-row board game vs AI or another player
- **Planet Merge** (`planet-merge.html`) - Suika-style physics merge game (hand-rolled circle physics, daily challenge; daily + alltime leaderboards served by the shared `game-scores` Worker as `planet-merge` / `planet-merge-d<YYYYMMDD>`)
- **Word Daily** (`word-daily.html`) - Bilingual daily word puzzle (EN 5-letter words / ZH 成语 with definitions; package in `src/games/word-daily/`; global aggregate stats Worker in `Workers/word-daily-stats.js`, KV binding `WORD_STATS`); DOM-only, no game loop
- **Hoop Shot** (`hoop-shot.html`) - Flick-basketball arcade (one miss ends the run, fire-mode streaks, hand-rolled projectile physics; leaderboard served by the shared `game-scores` Worker as `hoop-shot`)
- **Minesweeper** (`minesweeper.html`) - Classic logic puzzle (safe first click, iterative flood reveal, chording, long-press/right-click flags; fastest-clear leaderboard per difficulty)
- **Reversi** (`reversi.html`) - Othello strategy board game (negamax + alpha-beta AI with three levels and an endgame solver, pass-and-play mode, CSS 3D disc flips; global win-streak leaderboard)
- **Tower Defense** (`tower-defense.html`) - Future-city energy defense (pulse/frost/cannon/tesla towers, six operations with 15/20/25/30/35/40 waves, upgrades & 70% sell-back, ×2 speed; 800×600 / 20×15 immersive battlefield; global score leaderboard)
- **Gravity Slingshot** (`gravity-slingshot.html`) - Original orbital physics puzzle: pull-back slingshot launch, softened inverse-square gravity, fixed 1/120s substep integration shared by the trajectory preview and real flight (fully deterministic); 20 handcrafted holes (bodies may carry `tone`/`ring` visual props) with star ratings + a **daily course** (5 holes seeded from the UTC+8 date, generated with a ballistic sampler that verifies solvability and honest par); daily score = total launches, posted to per-day leaderboard keys `gravity-d<YYYYMMDD>` (asc) handled by the shared game-scores Worker
- **Lumen 折光** (`lumen.html`) - Beam refraction puzzle (design: `docs/proposal-lumen-challenge.md`): tap mirrors to flip `/`↔`\`, light every crystal `*` and keep shadow crystals `x` dark; decoy mirrors, linked mirrors (same-colour ring flips together) and beam splitters (reflect + transmit). Package `src/games/lumen/` is layered (imports only point down, locked by `tests/verify-lumen-modules.mjs`): `i18n`/`storage`/`audio` → `model/` (pure: `beam.js` grid/trace/tap, `solver.js` 2^u full enumeration — true par, unique optimum, "foresight" = taps with no visible progress, greedy-bot 3★ rate; `levels.js` 5 chapters × 5 levels written from `tools/generators/lumen-levels.mjs` candidates then decoupled, plus a 24-layout two-beam daily scrambled per UTC+8 day by `solver.scramble`, board `lumen-d<YYYYMMDD>`; `session.js` `PlaySession`, the only writer of grid/trace/flips, whose `tap()` returns change events) → `systems/records.js` (the only storage user: stars by level id in `game:lumen:v2:stars`, protocol keys `lm_daily_*`/`lm_local_*`) → `render/` (`geometry`, pure `pieces` painters, `effects` tweens/particles, `board` DPR + frame compositor; the only `getContext`) → `input/pointer.js` → `ui/` (`view.js` DOM/HUD/panels, `daily-board.js` the only leaderboard-network user) → `runtime.js` (state machine + wiring only; no drawing, DOM building, storage or network) → `index.js`. Difficulty floors (greedy bot can't par-solve) are locked by `tests/verify-lumen-levels.mjs`, session behaviour by `tests/verify-lumen-session.mjs` — rerun them after touching levels, solver or session
- **Pinpoint Clash: Needle vs Awn 针尖对麦芒** (`needle-awn.html`) - Cyber-ink martial precision action duel: head-on tip-to-tip clash mechanics with hit-stop time dilation, dual stances (Silver Needle bullet-time thrust vs Golden Awn solar nova sweep), Awakened Lotus ultimate, 10 handcrafted trial stages with bosses, endless survival, seeded daily duel, and 1v1 arena duel (vs AI or 2P local); leaderboard uses `needle-awn-endless` and `needle-awn-d<YYYYMMDD>` with visible shared dialog; historical `needle-awn` key stays allowlisted for existing records but receives no new mixed-mode submissions
- **Sword Flight 御剑飞行** (`sword-flight.html`) - Oriental Xianxia kinetic soaring action: smooth flight physics with aerodynamic banking, multi-segment cloth & tassel simulation, 9 handcrafted celestial stages, endless flight, seeded daily realm, and zen meditation flight; thread celestial rings for pentatonic harmonies, perform invincible sword qi dashes to cleave crags and absorb tribulation thunder, ascend through cultivation realms (炼气 -> 筑基 -> 结丹 -> 元婴 -> 化神 -> 渡劫) to command companion sword formations and unleash the screen-clearing Thousand Swords ultimate; leaderboard served by the shared `game-scores` Worker as `sword-flight` and `sword-flight-d<YYYYMMDD>`
- **Firefly Signal 萤火信号** (`firefly-signal.html`) - Midsummer-night synchrony puzzle (gameplay prototype, 3 levels: First Light / Two Meadows / Midsummer): tap a firefly to flash it and pull every firefly inside its ring toward "now"; natural pulse coupling only captures near-in-phase neighbours (capture window), so local groups sync on their own but antiphase meadows never merge without the player. Modules in `src/games/firefly-signal/` — `simulation.js` (pure, fixed 1/60s step, `mulberry32` seed, same seed + same `(tick, id)` inputs = bit-identical result), `renderer.js` (cached scenery + "lit" layer masked by a low-res light buffer = environmental lighting; hand-painted layers in `assets/firefly-signal/layers/*.webp` — sky/moon/mountains/lake/mid/fore + `fore-lit` additive light delta — load async with the procedural scene as fallback; distant fireflies draw behind the `fore` layer, near ones in front; painted lit twins must be occluded by nearer layers' silhouettes), `levels.js`, `audio.js`, `game.js`, `index.js`. Keyboard / screen-reader path: the canvas is a focusable `role="application"` — arrows move a focus ring between fireflies, Enter/Space intervene through the same `interveneOn()` as taps (same debounce + cooldown), H reads harmony, announcements go to the `#fs-sr-status` live region (covered by `smoke-firefly-signal` ⑧). First page on the **Immersive Stage** layout (`"layout": "immersive"` in `games.config.json`, `docs/contracts/layout.md` §7). Dark-only; per-level global leaderboard ranks fewer interventions first, then higher harmony; no daily yet. Level playability (idle never wins, solver wins within budget, rapid random clicking ≤30%) is locked by `tests/verify-firefly-signal-sim.mjs` using the test-only player models in `tests/lib/firefly-solver.mjs` — rerun it after touching levels or tuning
- **Shadow Loom 影织** (`shadow-loom.html`) - Paper-theatre shadow puzzle (design: `docs/proposal-shadow-loom-design.md`, art refs `assets/shadow-loom/`): drag paper cut-outs hung at different depths (and, from chapter 3, the lamp) until their shadows weave into the target silhouette. One projection model `S = L + (P − L) / z` in `src/games/shadow-loom/model/rules.js` feeds both rendering and judging (4px mask grid over the 356×424 paper window, IoU + per-piece contour score, thresholds in `THRESHOLDS`); level solutions are written as shadow centres so every level is solvable by construction (`src/games/shadow-loom/model/levels.js`, checked by `tests/verify-shadow-loom-levels.mjs`). Stage is 480×854 (9:16, same as the concept art); scenery is the layered art in `assets/shadow-loom/layers/` (1080×1920 = logical ×2.25; `manifest.json` is the coordinate contract) drawn by `src/games/shadow-loom/render/scene.js` — the paper window `SCREEN` is the frame layer's window after the frame is drawn at `FRAME_SCALE` 1.2 anchored on its feet (the manifest's native window is too small on phones), and the lamp is deliberately scaled down and drawn above the foreground (design doc §19.3). Authored silhouette SVGs are the source of truth for all eight playable levels (pieces are smooth partitions of each `target.svg`, cut with `tools/generators/shadow-loom-recut-pieces.mjs`); `tools/generators/shadow-loom-build-silhouettes.mjs` samples them into the generated runtime cache, and both `--check` plus `tests/verify-shadow-loom-silhouettes.mjs` run in `npm run verify`. Dark-only; per-level global leaderboard ranks time then moves from one completed run (never mix independently saved local minima); canonical progress is `game:shadow-loom:v1:progress`; `sl_progress` is retained only as the legacy import key
- **Loop Jail 画牢** (`loop-jail.html`) - Neon line-drawing arcade game on the **Immersive Stage** layout: drag to lay ink (mouse moves the pen, hold to draw; touch draws on drag), cross your own line to close a loop and capture every monster inside (loops < 1500px² are ignored); monsters touching an open line bite the whole line off. Package in `src/games/loop-jail/` — `simulation.js` is pure and deterministic (`mulberry32` seed; geometry, ink 100 / 0.045 per px / 5 per s / +6 per capture, pink bouncers 50, orange dashers 120 that lock the pen and dash after a 0.35s charge, green splitters 80/40/20 with a 0.6s split grace, endless waves `3+n` / `min(n,4)` / `min(1+⌊n/2⌋,4)` capped at 18, power-ups double pen / shield / ink every 14–22s, max 2; score = (base sum + area/80) × (1 + 0.5 × (n−1))). The world keeps a constant area (`WORLD_AREA`) while its aspect follows the stage, so every device plays the same field; `renderer.js` scales it into the canvas and owns all particles / flashes / floaters; `runtime.js` is the state machine (`menu`/`playing`/`over` + `isPaused`), manual pause overlay (P / Esc / topbar / background tab, never auto-resumes), contextual topbar restart (progress = `strokes`), shared `pauseOwnership` for the ranking dialog. Dark + light (`--lj-cv-*` palette via `bindPalette`). Global all-time leaderboard `loop-jail` (desc, dialog UI; only finished runs with score > 0). Locked by `tests/verify-loop-jail-sim.mjs` (offline: geometry, scoring, ink, bites, shield, splits, waves, power-ups, determinism, playability bots in `tests/lib/loop-jail-bot.mjs`) and `tests/smoke-loop-jail.mjs` (real touch / mouse loops, bite, pause, background, game over + score POST, language, rotation) — rerun the sim verifier after tuning
- **Sudoku in the Mist 雾隐九宫** (`sudoku-mist.html`) - Fog-of-war deduction sudoku (gameplay prototype; design + P0/P1 records in `docs/proposal-sudoku-mist-design.md`): standard 9×9 rules, but cells start hidden in mist; every correct placement clears the mist around it (`box` 3×3 or `cross` kernel per level, revealed clues never chain) and digits may be placed straight into the mist (×1.5). Scored by reasoning depth, not speed: a placement's tier = the minimal human-technique tier (T1 box single / last cell, T2 line single / one candidate, T3 locked candidates / pairs, T4 triples / X-Wing) that deduces it from what is visible at that moment; lucky guesses and hinted cells score 0, wrong digits are rejected (−20), streak up to ×2. Package `src/games/sudoku-mist/`: `model/` is pure and deterministic (technique ladder + min-tier closure, fog, scoring, `session.js` with `replay()`; only `view()` reaches the renderer and fogged cells never carry a digit), `model/generator.js` builds puzzles fog-first (whole solution hidden → widen window until solvable → dig while the fogged path stays solvable); runtime-generated daily puzzles are frozen by golden hashes + `GENERATOR_VERSION` (bump it and the golden values together); the 8 chapter levels in `model/levels.js` are written by `tools/generators/sudoku-mist-levels.mjs --write` and are decoupled from the generator afterwards. `render/board.js` is the DOM grid (81 buttons, keyboard + screen reader) above the `render/mist.js` canvas (27×27 density field + drifting wisps, colours via `bindPalette` `--sm-cv-*`). Standard layout, all page CSS in `@layer pages`, dark + light. **Daily mist** (P2, design §16): one ranked attempt per UTC+8 day — progress `{ seed, rev, inputs, elapsed, notes }` saved to `game:sudoku-mist:v1:daily-run:<YYYYMMDD>` after every input and restored with `replay()`; only one tab can be in the ranked run at a time (`daily-run.js`: Web Locks `sudoku-mist:daily:<date>`, released on menu / finish after flushing unsaved progress, or on tab close; failed writes retain the lock and show a warning; a second tab is refused), and an in-memory checkpoint keyed by `rev` covers failed writes, no restart while ranked, first clear writes `game:sudoku-mist:v1:daily:<YYYYMMDD>` and submits once to the daily-only dialog board `sudoku-mist-d<YYYYMMDD>` (the run's own date); later runs are unranked practice. Chapter levels carry `stars: [★2, ★3]` score thresholds computed by `starThresholds()` in `tests/lib/sudoku-mist-bot.mjs` and written by the levels tool. Not in the homepage Daily Hub. Locked by `verify-sudoku-mist-model` / `-levels` / `-daily` / `-daily-run` (offline; rerun `sudoku-mist-levels --write` + `-levels` after touching techniques, fog or scoring) and `smoke-sudoku-mist`
- **index.html** - Game collection landing page (links out to external games too); its Daily Hub shows 3 tasks: Word Daily (`wd_daily_*`), Planet Merge (`pm_daily_*`), Gravity Slingshot (`gs_daily_<YYYYMMDD>`, written when the daily course is finished)

## Architecture

### Build & Deploy
```bash
npm run dev         # Vite dev server
npm run build       # Vite production build -> dist/ (multi-entry, legacy plugin, terser)
npm run deploy      # vite build && wrangler deploy
npm run deploy:analytics   # 统计 Worker（games-analytics）
npm run deploy:scores      # 排行榜 Worker（game-scores）
npm run deploy:word-stats  # Word Daily 统计 Worker
npm run deploy:all         # 主站 + 以上三个 Worker；改了 games.config.json 并 gen 后用它
# 无本地 wrangler 时：GitHub → Actions → Deploy Workers → Run workflow（.github/workflows/deploy-workers.yml，仅 main，需 CLOUDFLARE_API_TOKEN / CLOUDFLARE_ACCOUNT_ID secrets）
npm run preview     # wrangler dev (serves dist/ + src/index.js worker)
npm run gen         # 由 games.config.json 重新生成全部登记点（见 registry 契约）
npm run verify      # 全量校验体系（自动发现的全部项，见 Testing）
npm run verify:quick  # 日常档（自动发现的离线项 + QUICK_BROWSER）
npm run verify:changed  # 按 git diff 只跑相关项（单页改动约 40s；动了共享文件自动退回全量）
```

To add a game: add its entry (with a `scores` block) to `games.config.json`, then `npm run gen`. The authoritative per-game list is that file, not this bullet. See `docs/contracts/registry.md`. Deploy config: `Workers/wrangler-game-scores.jsonc`.

### Shared infrastructure
- `src/platform/player.js` — global player identity: all games read/write `localStorage.player_name` (auto-migrates legacy `tetris_username`/`pm_username`/`hs_username`); landing page edits it too
- `src/platform/site-settings.js` — **site-wide settings, the single entry point for language & sound**: canonical keys `site_lang` (`'en'|'zh'`, also written by the landing page) and `site_muted` (`'1'|'0'`); first read migrates legacy per-game keys (`pm/hs/wd/ms/rv/td/gd_lang`, `*_muted`, `tankBattleLanguage`); writes dispatch a `site-settings:changed` event, cross-tab sync is the native `storage` event. Every game reads language through `getLang()` and sound through `getMuted()/setMuted()` — never write per-game `_lang`/`_muted` keys in new code
- `src/platform/icons.js` — inline SVG icon set (`ICONS.home/soundOn/soundOff/pause/play/retry/close/flag/copy/check/mine/help/stats/calendar/dice/share/arrowRight/trophy`, 24×24 stroke=currentColor) for **icon-only control buttons and text-labeled action buttons**; JS stateful toggles (mute) and i18n text rewrites set `innerHTML` from it (`${ICONS.x}<span>${text}</span>`). Text-labeled buttons that carry an icon must also take `game-btn` (see the layout contract bullet) — it is the composition primitive that makes the label+icon an `inline-flex` row and sizes the icon to 15px. Standard result/action surfaces additionally take `game-action-btn` plus `game-action-btn--primary` / `--ghost` where appropriate; their rows use `game-action-row`. Do not copy page-local `.xx-btn` geometry for a standard action. Special mode/ability/gameplay controls may keep their own surface while reusing `game-btn` only for composition. Emoji policy (icons.js note + 2026-09-18 audit): text-labeled **result/action** buttons (Play/Again/Retry/Copy/Close/Home/Share/Stats/Next) use themed inline SVG on every page; emoji remain only for (a) game-content glyphs (Minesweeper cells/faces, Planet Merge chains), (b) decorative hero art, (c) the more-games strips, (d) start-menu mode/ability tiles carrying descriptive text (`♾️ Endless`, `🔄转锋`, `❄️ Freeze`), and (e) section titles / toast & announcement copy (`🏆 Global Top 10`, `🎉 You win!`). ⚠️ A button emoji can hide in **three** layers — the static HTML, the JS `applyLanguage` rewrite, **and the i18n string itself** (`needle-awn`/`sword-flight` had `home: '返回菜单 🏠'`). Replacing only the markup gets silently overwritten; audit with `python tools/checks/emoji-button-audit.py`; update HTML, runtime rewrites, and i18n manually, then run `node tests/verify-button-icons.mjs`

## Development Workflow

### Branch and PR workflow

- `main` is the only long-lived integration and release branch.
- Create a topic branch from the latest `main`: `feature/*`, `fix/*`, `docs/*`, or `art/*`.
- Open a pull request directly from the topic branch to `main`. Do not route changes through or create a permanent `develop` branch.
- Do not push directly to `main`. Keep unrelated work in separate topic branches.

### Testing — `npm run verify`（verify-all.mjs）
Puppeteer-core 驱动的真浏览器校验体系；**提交前必须全绿**。编排器自动起静态服务器 → 并发跑 → 汇总 → kill。项目清单由 `tests/verify-all.mjs` 按 `verify-*.mjs` / `smoke-*.mjs` 文件名自动发现，并根据导入推断服务器需求。

- **离线项**（无需浏览器）：`gen-check`（gen 漂移）、`lint`（eslint+stylelint）、`boot`（禁 DOMContentLoaded 复活）、`daily`（时区/哈希黄金值）、`leaderboard`、`i18n`、`sfx`、`registry`（caps ⟺ 代码事实）
- **在线项**（需服务器 + Chrome）：`fg-audit`、`placeholder-leak`、`chrome`、`desktop-frame`、`stats-drawer`、`gomoku`、`button-icons`、`tetris-topbar-mobile`、`tetris-touch`、`tetris-drawer`、`smoke-index`、`smoke-tank-battle`、`smoke-math-rain`
- 三档：`verify:changed`（改动相关项，日常首选）→ `verify:quick` → `verify`（PR 前 / 动了共享层）；复验 dist 产物：`npm run build && npm run verify:dist`（`--dist` 起 dist/ 服务器，并发跑 `DIST_SUITE` 的构建产物门禁）
- CI 拆分（`.github/workflows/architecture-v2.yml`）：`--offline`（只跑离线项）、`--browser --shard=k/n`（浏览器项按 `WEIGHTS` 做 LPT 均衡分片，每项恰好落在一个分片）、`--dist`；三类 job 并行，墙钟取最慢分片。新增慢校验器（CI 上 >30s）时把实测秒数补进 `tests/verify-all.mjs` 的 `WEIGHTS`，只影响均衡，不影响覆盖
- 萤火信号专项：`firefly-signal-sim`（离线：模拟单元 + 确定性回放 + 关卡可玩性）、`immersive`（Immersive Stage 几何 × 6 视口）、`smoke-firefly-signal`（真实点击通关 + 浏览器模拟指纹 == Node 回放）
- 新校验器只需放入 `tests/` 并使用 `verify-*.mjs` / `smoke-*.mjs` 文件名；离线校验器自动进入 `--quick`，浏览器 smoke 默认只进入 full suite，除非加入 `QUICK_BROWSER`。**逐页循环的跨页校验器必须接 `tests/lib/page-filter.mjs`（`keepPage` / `exitIfNoPages`）并标 `pages: true`**，否则 `--changed` 下它要么全页跑（慢），要么被漏掉；页专属校验器名字里带页 id（`smoke-<id>` / `<id>-levels`），`--changed` 靠名字归属，带不了就写 `games: [...]`
- 并发与提速：离线项全并发，浏览器项 `--jobs=N`（默认 `min(3, CPU/2)`，`VERIFY_JOBS` 可覆盖）；并发时每项输出缓冲成整块打印，排查单项用 `--jobs=1` 回到串行直通。新写在线校验器别用 `networkidle2` + 固定 sleep 当就绪条件 —— 用 `waitUntil: 'load'` + 显式条件（见 `docs/traps.md`「校验基础设施」）。单个跨页校验器可直接 `VERIFY_PAGES=silk-dew,index node tests/verify-theme.mjs <base>`
- Chrome 查找（`tools/lib/browser.mjs`）：`CHROME_BIN` → 系统路径 → puppeteer 缓存 → `PLAYWRIGHT_BROWSERS_PATH` 下的 Chromium（云端容器无需手设）
- 几何检查测不出可玩性：真实验证 = canvas 位图像素 + `elementFromPoint` + 真实点击；结算态与 i18n 文案必须专门断言 + 反向验证（旧版本跑同一断言必须失败）

## Code Patterns

### Game Structure
Each game follows this pattern:
```javascript
// Game state and configuration
let gameState = {...};

// Game loop with requestAnimationFrame (render-only games like Gomoku redraw on demand)
function gameLoop() {
    update();
    render();
    requestAnimationFrame(gameLoop);
}

// Input handling with both keyboard and touch
document.addEventListener('keydown', handleInput);
canvas.addEventListener('touchstart', handleTouch, { passive: false });
```

  - Use the **quiet** variants, not the page's normal pause: the ordinary one shows the "Paused" overlay, which would flash behind the open drawer. `openDrawer()` only pauses when `isBusy()` is true and records `pausedByDrawer`; `close()` resumes **only** a drawer-induced pause, so a user who paused first stays paused
  - Esc is bound in the **capture** phase with `stopPropagation`, otherwise the page's own `keydown` handler keeps driving the board behind the open drawer; the drawer also owns a Tab focus trap, a scrim-click close, and closes itself when `matchMedia` flips to desktop
- i18n strings may contain `{n}` / `{g}` / `{who}` / `{lives}` placeholders. Expand them at a **single** helper per game (e.g. `WordDailyGame.guessPlaceholderText()`), never at several call sites — a duplicated assignment without `.replace()` silently overwrites the expanded value with the literal token. - **Desktop stage budget contract** (added 2026-09-19) — on ≥1024px viewports the canvas games carrying the `frame-budget` cap (gd/hs/pm/na/sf + tetris) derive stage width from available height × aspect ratio (`--stage-w = min(--frame-stage-h, 100dvh - --frame-chrome) × --frame-ratio`), replacing the fixed `--frame-max-wide` cap; the page always fits one screen.
